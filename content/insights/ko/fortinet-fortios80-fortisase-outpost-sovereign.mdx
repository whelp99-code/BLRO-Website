## 한눈에 보기

Fortinet은 2026-03-10에 FortiOS 8.0을 발표하며 SASE Outpost와 주권형 SASE 배치를 적습니다. 2026-07-28에는 FortiGate 1200G와 FortiSASE Outpost를 적습니다.

영향 범위는 FortiSASE를 클라우드 POP로 쓸지, 고객 위치 Outpost로 쓸지, 91G·901G에 주권형 라이선스를 쓸지입니다. 전제는 사이트마다 배치가 다를 수 있다는 점입니다. 검증 항목은 사이트별 클라우드 POP와 온프레미스 Outpost, 91G·901G에서 config system sov-sase를 켜기 전에 로컬 GUI와 CLI가 읽기 전용이 된다는 기록입니다.

- 결정: 사이트별로 클라우드 POP를 쓸지, 온프레미스 Outpost를 둘지
- 전제: 1200G는 확인일 기준 Q3 2026 출고 예정이다. 이미 모든 사이트에 있다고 보지 않는다
- 검증: 91G·901G에서 sov-sase를 켜기 전에 로컬 변경이 막힌다고 문서화했는지
- 범위: SASE·SD-WAN 역할 글의 재작성이 아니다. Outpost와 주권형 배치만 가른다

## 문제 상황

FortiOS 8.0으로 올린다고 보고하면, 클라우드 POP, 온프레미스 Outpost, 주권형 라이선스, 1200G 출고, 91G·901G 읽기 전용이 한 완료로 섞입니다.

2026-03-10 보도자료는 FortiOS 8.0의 SASE Outpost를 고객이 통제하는 위치, 온프레미스, 프라이빗 데이터센터, 코로케이션에 SASE POP를 두고 클라우드에서 중앙 관리한다고 적습니다. 주권형 SASE는 지역 로그 보관, 컨트롤 플레인 상주, 주권 POP, 고객 데이터센터 안 완전 주권 배치를 고를 수 있다고 적습니다. AI 기능과 양자내성 항목을 이 배치 결정과 한 문장으로 합치지 않습니다.

2026-07-28 보도자료는 FortiGate 1200G 시리즈와 FortiSASE Outpost를 적습니다. Outpost로 설정하면 1200G가 고성능 로컬 SASE POP로 동작한다고 적습니다. 트래픽은 클라우드 SASE POP로 보내거나, 민감하거나 지연에 민감한 트래픽은 고객 환경의 FortiGate Outpost에서 처리할 수 있다고 적습니다. Fortinet 운영 POP, 온사이트 POP, 또는 둘 다를 쓸 수 있고, FortiSASE 인터페이스가 구성, 정책, 모니터링, 수명 주기, 업그레이드를 양쪽에서 중앙 관리한다고 적습니다. FortiGate 1200G는 Q3 2026 출고 예정입니다.

FortiOS 8.0.0 릴리스 노트 New features or enhancements는 FortiGate 91G와 901G의 FortiSASE Sovereign 라이선스 번들을 적습니다. 라이선스를 적용한 뒤 아래 CLI를 설정하면 GUI와 CLI가 읽기 전용으로 제한됩니다.

config system sov-sase

set status enable

end

설정 이후 모든 FortiGate 구성 변경은 FortiSASE Sovereign Cloud Orchestrator와 Web Portal에서 관리된다고 적습니다. 이 읽기 전용 전환을 1200G Outpost 일반 배치와 같은 스위치로 보지 않습니다.

릴리스 노트는 Outpost 하드웨어 일반화나 1200G 출고일을 이 항목에 적지 않습니다. 보도자료의 Outpost와 RN의 sov-sase를 한 명령으로 합치지 않습니다.

## 지금 결정할 것

- 사이트별로 클라우드 POP를 쓸지, 온프레미스 Outpost를 둘지
- 지연·대역폭·데이터 상주 때문에 Outpost가 필요한 사이트를 목록화할지
- 1200G Outpost를 Q3 2026 출고 전제로 일정을 짤지
- 91G·901G에 FortiSASE Sovereign 라이선스를 쓸지
- config system sov-sase를 켜기 전에 로컬 GUI·CLI 읽기 전용을 변경 창에 문서화할지
- 읽기 전용 이후 변경 책임을 Orchestrator와 Web Portal로 옮길지

## 의사결정 기준

### 사이트 배치를 제품 버전보다 먼저 가릅니다

보도자료는 클라우드 POP와 온사이트 POP를 사이트 요구에 따라 고르라고 적습니다. FortiOS 8.0 설치만으로 Outpost가 켜진다고 보지 않습니다.

### Outpost와 주권형 라이선스를 같은 스위치로 보지 않습니다

Outpost는 고객 위치 POP입니다. 91G·901G의 sov-sase는 Sovereign 라이선스 뒤 로컬 GUI·CLI를 읽기 전용으로 만듭니다. 한 명령을 두 배치의 완료로 쓰지 않습니다.

### 로컬 읽기 전용을 되돌릴 수 있는 일반 설정으로 보지 않습니다

릴리스 노트는 설정 이후 구성 변경이 Sovereign Cloud Orchestrator와 Web Portal로 옮겨진다고 적습니다. 켜기 전에 로컬 운영 절차가 남는다고 문서화하지 않으면 승인하지 않습니다.

### 1200G 출고 예정과 현재 보유를 같은 상태로 보지 않습니다

1200G는 Q3 2026 예정입니다. 확인일 기준 모든 사이트에 Outpost 하드웨어가 있다고 보지 않습니다.

### 중앙 관리를 로컬 변경 유지로 읽지 않습니다

Outpost도 FortiSASE 인터페이스가 수명 주기를 중앙 관리한다고 적습니다. 91G·901G Sovereign은 로컬이 읽기 전용입니다. 중앙 관리와 로컬 쓰기 권한을 같은 말로 쓰지 않습니다.

## 실무 체크리스트

1. 사이트 목록을 클라우드 POP, 온프레미스 Outpost 후보, 둘 다로 나눕니다. 지연, 대역폭, 로그·처리 상주를 사이트별로 적습니다.
2. Outpost 후보 사이트에 둘 장비가 1200G 예정인지, 다른 FortiGate인지 기록합니다. 1200G는 Q3 2026 출고 예정입니다.
3. 91G와 901G에 FortiSASE Sovereign 라이선스를 적용할지를 따로 적습니다. Outpost 후보와 자동으로 합치지 않습니다.
4. 91G·901G에서 config system sov-sase를 켜기 전에, 로컬 GUI와 CLI가 읽기 전용이 되고 이후 변경은 Orchestrator와 Web Portal로만 간다는 점을 변경 설명에 적습니다.
5. 읽기 전용 전환 후 로컬 긴급 변경 경로가 있는지를 벤더 문서에서 다시 확인합니다. 이 초안은 우회 절차를 확정하지 않습니다.
6. FortiOS 8.0의 AI, MCP, 양자내성 항목을 Outpost 배치 승인에 넣지 않습니다.
7. SASE·SD-WAN 역할 글의 일반 역할을 이 하드웨어·라이선스 결정의 근거로 쓰지 않습니다.

## 제외 범위

- FortiOS 8.0 AI·양자내성 기능의 재작성
- 1200G를 확인일 기준 일반 공급으로 보는 해석
- 91G·901G sov-sase를 모든 FortiGate Outpost의 필수 명령으로 보는 해석
- 로컬 읽기 전용 이후의 긴급 우회 절차를 이 초안이 확정하는 범위
- 타사 SASE와의 기능, 성능, 가격 비교
- SASE·SD-WAN 역할 글을 다시 쓰는 범위
