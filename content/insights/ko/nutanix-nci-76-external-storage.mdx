## 한눈에 보기

Nutanix Cloud Infrastructure 7.6은 AHV 11.2와 함께 외부 스토리지와 용량 지표, GPU 가상머신 프로필을 한 릴리스에 넣습니다. 먼저 갈라야 할 것은 로컬 HCI 용량과 Dell PowerStore를 Prism Central에서 붙일지입니다.

- 결정: 컴퓨트 클러스터에 PowerStore를 붙일지, 로컬 스토리지만 유지할지
- 관리: 외부 스토리지를 Prism Central에서 보고, Prism Element로 넘기지 않을지
- 용량: 메모리 오버커밋 지표를 승인 조건으로 쓸지
- 범위: Azure Local이 아니라 Nutanix AOS와 AHV. VMware 평가 행렬은 열지 않는다

## 문제 상황

HCI 업그레이드를 용량 숫자만으로 승인하면, 외부 스토리지 연결과 GPU 프로필과 오버커밋 지표가 한 변경 창에 섞입니다.

Nutanix 제품 블로그는 NCI 7.6에서 Dell PowerStore 1세대, 2세대, 3세대 일반 지원을 안내합니다. 제품 업데이트는 외부 스토리지를 Prism Central에서 관리하고, Nutanix 컴퓨트 클러스터에 PowerStore를 붙이며, PowerStore 재해복구로 동기와 비동기 복제와 클러스터 사이 라이브 마이그레이션을 적습니다. 컨트롤러 VM과 Prism Central 기반을 RHEL 9로 바꾼다고 적습니다.

기술센터 메모리 글은 NCI 7.6에서 AHV 인프라 지표를 30개 넘게 넣고, 가상머신과 호스트와 클러스터 계층에서 풍선, 스왑, 오버커밋 비율을 본다고 적습니다. 회수 가능 메모리는 오버커밋 가상머신에 최소 25퍼센트를 남겨 둔다고 적습니다. 새 지표는 Prism Central V4 API로도 열립니다.

기술센터 GPU 글은 AHV 11.2와 함께 AI 최적화 가상머신 프로필을 안내합니다. 프로필 이름은 GPU와 NIC 조합을 담고, Ads가 배치를 고릅니다. 모든 다중 GPU 가상머신이 NVSwitch나 NUMA를 필요로 하지는 않는다고 적습니다. 성능 수치와 우열은 이 글의 결정 대상이 아닙니다.

포털 릴리스 노트는 로그인 뒤에 있습니다. 운영 승인은 열린 제품 업데이트와 기술센터 페이지를 기록하고, 적용 전에 포털 릴리스 노트를 다시 열라고 남깁니다.

## 지금 결정할 것

- 이번 업그레이드에서 PowerStore를 컴퓨트 클러스터에 붙일지, 로컬 스토리지만 올릴지
- 외부 스토리지 관리를 Prism Central로 옮길지
- 컨트롤러 VM과 Prism Central의 RHEL 9 기반을 같은 창에 넣을지
- 메모리 오버커밋 지표를 용량 승인 조건으로 쓸지
- GPU 프로필이 필요한 워크로드와 일반 가상머신을 나눌지

## 의사결정 기준

### 외부 스토리지와 로컬 HCI를 한 줄로 합치지 않습니다

제품 업데이트는 PowerStore를 외부 스토리지로 붙이는 일과 로컬 노드 용량 확장을 따로 적습니다. PowerStore를 쓰지 않으면 외부 스토리지 재해복구 항목을 변경 범위에 넣지 않습니다. 로컬 노드의 1노드 2디스크 내결함성과 하이브리드 용량은 다른 줄입니다.

### 관리 평면은 Prism Central을 전제로 적습니다

외부 스토리지를 Prism Element에서 이어서 관리한다는 가정을 승인 조건에 넣지 않습니다. 제품 업데이트는 Prism Central에서 관리한다고 적습니다. 컨트롤러 VM과 Prism Central의 RHEL 9 전환도 같은 릴리스에 있습니다.

### 오버커밋 지표를 밀도 보장으로 읽지 않습니다

기술센터는 풍선과 호스트 스왑과 회수 가능 풀을 보여 준다고 적습니다. 회수 가능 값은 최소 25퍼센트를 남긴 뒤의 숫자입니다. 지표가 보인다고 해서 더 많은 가상머신을 켜도 된다는 승인을 자동으로 내지 않습니다. 내부 한도를 정한 뒤에 경보를 붙입니다.

### GPU 프로필은 특정 하드웨어 전제입니다

AI 최적화 프로필은 HGX와 같은 구성에서 GPU와 NIC 조합을 고릅니다. 일반 가상머신 업그레이드에 프로필을 기본값으로 두지 않습니다. 성능 비교나 베어메탈 대비 수치는 승인 근거로 쓰지 않습니다.

## 실무 체크리스트

1. 클러스터를 로컬 스토리지만, PowerStore 연결 예정, GPU 프로필 필요로 나눕니다.
2. 현재 AOS, AHV, Prism Central 버전과 RHEL 9 전환 대상 컨트롤러 VM을 기록합니다.
3. 외부 스토리지를 Prism Central에서 볼지, 재해복구를 동기와 비동기 중 무엇으로 둘지 적습니다.
4. 포털 릴리스 노트를 로그인 후 다시 열고 제품 업데이트와 다른 줄을 남깁니다.
5. 메모리 오버커밋을 쓰는 가상머신과 쓰지 않는 가상머신을 표시합니다.
6. 클러스터 오버커밋 한도와 경보 담당을 정합니다.
7. GPU 프로필이 필요한 호스트와 일반 호스트를 분리합니다.
8. 업그레이드 후 외부 스토리지 상태와 지표 API 경로를 확인합니다.

## 제외 범위

- Azure Local 업데이트나 iSCSI SAN 글의 재작성
- VMware와 Nutanix 평가 행렬의 확장. 그 문서는 비공개 검토로 유지한다
- 특정 HCI 제품의 우열, 가격, 성능 비교
- 오버커밋이나 GPU 프로필이 용량이나 처리량을 보장한다는 주장
- 고객별 클러스터 이름, 계정, 웹훅의 공개
