## 한눈에 보기

Prometheus 3.14.0 릴리스 노트는 날짜를 2026-08-17로 두고, GitHub는 2026-08-18에 게시했습니다. OTLP 향상 항목은 살균 뒤 속성 이름이 같은 Prometheus 라벨로 겹치면 경고를 낸다고 적습니다.

- 결정: 3.14 OTLP 수집을 올리기 전에 살균 후 충돌을 수용할지, 보내는 쪽 이름을 고칠지
- 전제: 예시는 k8s.pod.name과 k8s_pod_name이 둘 다 k8s_pod_name이 되는 경우다
- 관측: prometheus_api_otlp_translation_warnings_total을 category 라벨로 볼지
- 범위: first_over_time 안정화나 GCP Telemetry API OTLP, CloudWatch PromQL 글이 아니라 OTLP 라벨 충돌

## 문제 상황

OTLP를 켰다고 보면, 점과 밑줄이 다른 속성이 한 라벨로 합쳐져도 수집 성공으로 보입니다.

릴리스 노트와 CHANGELOG 3.14.0 절은 같은 문장을 반복합니다. OTLP는 살균 후 속성 이름이 충돌하면 경고를 내고, prometheus_api_otlp_translation_warnings_total 카운터를 category 라벨로 노출한다고 적습니다. 이슈 번호는 18957입니다. 같은 버전의 다른 CHANGE 항목은 first_over_time을 안정으로 올립니다. 그 함수 결정은 이 글의 대상이 아닙니다.

prometheus.io OTLP 가이드는 본문이 있는 페이지로 열렸습니다. 수신기는 기본 꺼짐이며 --web.enable-otlp-receiver가 필요하다고 적습니다. 기본 translation_strategy는 UnderscoreEscapingWithSuffixes이며 특수 문자를 밑줄로 바꿉니다. UTF-8을 켜도 이 기본값은 예전 정규화를 유지합니다. promote_resource_attributes 예시에는 k8s.pod.name이 들어 있습니다. 점이 밑줄이 되면 k8s_pod_name과 겹칠 수 있습니다. 가이드는 충돌 카운터를 적지 않습니다. 릴리스의 경고와 가이드의 기본 살균을 한 설정으로 평탄화하지 않습니다.

GitHub CHANGELOG blob이 아니라 raw CHANGELOG를 읽었습니다. 3.14.0 절 텍스트는 릴리스 페이지와 같습니다. 같은 변경 로그를 서로 다른 출처 두 개로 세지 않고, 날짜가 있는 릴리스와 가이드를 다른 종류로 둡니다.

## 지금 결정할 것

- 3.14 OTLP 수신을 운영에 올릴지, 살균 규칙을 먼저 맞출지
- k8s.pod.name과 k8s_pod_name처럼 겹치는 속성을 보내는 쪽을 고칠지, 충돌을 수용할지
- prometheus_api_otlp_translation_warnings_total을 전환 전 관측 항목으로 둘지
- translation_strategy를 기본 UnderscoreEscapingWithSuffixes로 둘지, UTF-8 전략으로 바꿀지
- --web.enable-otlp-receiver를 켜는 전제를 변경 창에 남길지
- first_over_time 안정화를 같은 승인에 넣을지. 넣지 않는다

## 의사결정 기준

### 수집 성공과 라벨 충돌 없음을 같은 검증으로 보지 않습니다

릴리스는 충돌 시 경고와 카운터를 적습니다. 샘플이 들어왔다고 해서 두 속성이 따로 남았다고 보지 않습니다. 전환 전에 경고 카운터를 누가 보는지 정합니다.

### 기본 살균과 UTF-8 허용을 한 스위치로 보지 않습니다

가이드는 저장소와 UI의 UTF-8과 OTLP translation_strategy를 구분합니다. 기본값은 UnderscoreEscapingWithSuffixes입니다. UTF-8이 켜져 있어도 OTLP 이름이 자동으로 점을 유지한다고 보지 않습니다.

### first_over_time 안정화를 이 결정에 넣지 않습니다

CHANGELOG는 first_over_time을 같은 버전에서 안정으로 올립니다. 그것은 PromQL 함수 플래그 결정입니다. OTLP 라벨 충돌 수용과 같은 변경 요청에 넣지 않습니다.

### 수신기 기본 꺼짐을 버전 업과 같은 전제로 보지 않습니다

가이드는 OTLP 수신기가 기본 꺼짐이며 CLI 플래그로 켠다고 적습니다. 3.14로 올렸다고 해서 OTLP 수집이 켜진 것은 아닙니다.

## 실무 체크리스트

1. 현재 Prometheus 버전과 3.14.0 대상 여부를 바이너리와 릴리스 태그로 확인합니다.
2. OTLP 수신 플래그와 translation_strategy 값을 기록합니다.
3. 보내는 쪽 속성 이름에서 점과 밑줄이 같은 라벨로 합쳐질 쌍을 찾습니다.
4. 충돌을 수용할지, 송신 이름을 바꿀지 정합니다.
5. prometheus_api_otlp_translation_warnings_total을 누가 어떤 주기로 볼지 정합니다.
6. promote_resource_attributes에 k8s.pod.name을 넣을 때 k8s_pod_name과 겹치는지 확인합니다.
7. first_over_time 플래그 제거는 별도 변경으로 분리합니다.
8. 올린 뒤 충돌 경고가 없는지를 수집 성공과 따로 기록합니다.
