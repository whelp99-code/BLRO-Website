## 한눈에 보기

Cloud Run 배포에 --functional-type=agent와 --identity-type=agent-identity를 같이 줄지, 서비스 계정만 유지할지부터 정합니다.

- 결정: 두 플래그를 쌍으로 주어 시스템 관리 Agent Identity와 Agent Registry 자동 등록을 쓸지, functional-type을 붙이지 않고 서비스 계정만 둘지
- 전제: 자동 등록 문서는 --functional-type=agent인 워크로드가 --identity-type=agent-identity를 반드시 지정해야 하고, 다른 identity type으로 배포하면 오류가 난다고 적는다
- 단계: Cloud Run 릴리스 노트 September 01, 2026과 Authenticate your AI agents 페이지는 이 경로를 Preview·Pre-GA로 적는다
- 범위: 에이전트 제품 우열이 아니라 Cloud Run 배포 플래그 쌍과 레지스트리 확인

## 문제 상황

에이전트를 Cloud Run 서비스나 Job으로 올리면, 호출 주체가 기존 서비스 계정인지 시스템 관리 Agent Identity인지가 같은 배포 명령 안에 섞입니다. 2026-09-01 릴리스 노트는 Agent Platform 기능으로 시스템 관리 Agent Identities를 쓰고 Agent Registry 자동 등록을 포함한다고 적으며, 둘 다 Preview입니다.

자동 등록 문서는 Cloud Run에 --functional-type=agent와 --identity-type=agent-identity를 같이 주라고 적습니다. functional-type=agent는 워크로드를 일반 컨테이너가 아니라 AI 에이전트로 표시해 Agent Registry가 introspection을 하게 합니다. 이 플래그만 주고 identity-type을 agent-identity가 아닌 값으로 두면 배포가 오류로 거절됩니다. 서비스 계정만 유지하려면 functional-type=agent를 붙이지 않아야 합니다. 두 선택을 한 배포로 합치지 않습니다.

Authenticate your AI agents 페이지는 Preview이며 Pre-GA Offerings Terms의 대상이라고 적습니다. agent-identity identity type이면 시스템 관리 신원이 principal://agents.global.org-ORGANIZATION_ID.system.id.goog/resources/run/projects/PROJECT_NUMBER/locations/REGION/services/SERVICE_NAME 형식입니다. 조직이 없으면 project-PROJECT_NUMBER 형식입니다. 이 신원으로 Vertex AI, Cloud Storage 등 Google Cloud API에 권한을 줄 수 있다고 안내합니다. 자동 등록은 같은 Google Cloud 프로젝트 안의 리소스만 발견합니다.

## 지금 결정할 것

- 대상 Cloud Run 서비스·Job에 두 플래그를 같이 줄지, 서비스 계정만 유지할지
- Preview·Pre-GA를 운영 승인에 넣을지, 평가 클러스터에만 둘지
- 자동 등록을 같은 프로젝트로 한정하는 조건을 수용할지
- 배포 후 gcloud agent-registry agents list와 콘솔 Agent Registry → Agents에서 런타임이 Cloud Run인지 확인할지
- Agent Identity principal에 Vertex AI 등 역할을 따로 줄지

## 의사결정 기준

### 두 플래그 쌍과 서비스 계정 전용을 한 배포로 보지 않습니다

자동 등록 문서는 두 플래그를 같이 쓰라고 적습니다. functional-type=agent인데 identity-type이 agent-identity가 아니면 오류입니다. 서비스 계정만 쓰려면 functional-type=agent를 주지 않습니다. 한쪽만 켠 상태를 성공으로 보지 않습니다.

### Preview 경로와 일반 공급 런타임을 한 승인으로 묶지 않습니다

릴리스 노트와 인증 문서는 Preview·Pre-GA입니다. 운영 승인에 넣으면 지원 범위와 변경 가능성을 같은 기록에 남깁니다. 평가와 운영을 한 클러스터 기본값으로 합치지 않습니다.

### 레지스트리 목록과 배포 성공을 같은 완료로 보지 않습니다

배포가 끝나도 같은 프로젝트·리전 레지스트리에 항목이 생겨야 자동 등록이 된 것입니다. 문서는 gcloud agent-registry agents list와 콘솔 Agent Registry의 Agents 탭을 보라고 적습니다. 목록에 Cloud Run 런타임이 보이는지로 확인합니다.

### 시스템 관리 신원과 기존 서비스 계정 IAM을 한 주체로 보지 않습니다

인증 문서는 agent-identity일 때 위 principal 형식을 줍니다. Vertex AI나 Cloud Storage 역할은 그 principal에 다시 할당합니다. 서비스 계정에 준 역할을 Agent Identity가 그대로 받는다고 보지 않습니다.

## 실무 체크리스트

1. 대상이 Cloud Run 서비스인지 Job인지 기록합니다. 자동 등록 문서는 둘 다 배포할 수 있다고 적습니다.
2. Preview·Pre-GA를 운영에 넣을지 평가에만 둘지 정합니다.
3. 에이전트로 등록할 배포에 --functional-type=agent와 --identity-type=agent-identity를 같이 줍니다.
4. 서비스 계정만 유지할 워크로드에는 functional-type=agent를 붙이지 않습니다.
5. 레지스트리 프로젝트가 배포 프로젝트와 같은지 확인합니다. 다른 프로젝트는 수동 등록입니다.
6. 배포 후 gcloud agent-registry agents list --project=PROJECT_ID --location=REGION을 실행합니다.
7. 콘솔 Agent Registry에서 Agents 탭을 열고 Runtime이 Cloud Run인 항목을 봅니다.
8. 「이번 주 운영 확인」 PASS = 두 플래그로 배포한 뒤 gcloud agent-registry agents list 또는 콘솔 Agent Registry → Agents에 해당 Cloud Run 에이전트가 있다. FAIL = --functional-type=agent만 주고 --identity-type=agent-identity를 빼 배포가 오류로 거절된다.
