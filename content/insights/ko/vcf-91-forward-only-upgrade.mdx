## 한눈에 보기

VMware Cloud Foundation 9.1은 2026-05-12 릴리스입니다. Broadcom은 플릿과 관리 도메인을 9.1로 올리는 일을 의무로 두고, 워크로드 도메인은 이후 Day-N으로 남겨 둡니다.

- 결정: 지금 올리는 범위가 관리 도메인인지, 워크로드까지인지
- 경로: 5.2 미만은 먼저 5.2.x. 5.2.x와 9.0.x는 표가 다름
- 정방향 제한: 현재 버전 출시일보다 이전인 대상 버전으로는 올리지 못함
- 범위: VMSA-2026-0006 패치 묶음이 아니라 9.1 수명주기 경로

## 문제 상황

vSphere 9.1 업그레이드를 호스트 패치처럼 보면, 플릿 관리 평면과 워크로드 도메인이 한 변경 창에 섞입니다.

vSphere 9.1 릴리스 노트 색인은 vSphere 9.1 내용을 VCF 9.1 릴리스 노트를 읽으라고 안내합니다. Deployment 문서는 기존 VCF 5.2.x 또는 9.0.x를 9.1로 올릴 수 있다고 적습니다. 현재 버전 출시일 이후에 나온 대상으로만 올릴 수 있고, 상호운용 행렬을 보라고 적습니다.

업그레이드 문서는 플릿 수준과 관리 도메인을 9.1로 올리는 일을 의무로 둡니다. 워크로드 도메인은 의무가 아니며 이후 Day-N으로 할 수 있습니다. 5.2 미만은 관리 도메인과 모든 워크로드를 먼저 5.2.x로 올린 뒤에야 9.1로 갈 수 있습니다.

정방향 제한 예시는 날짜가 어긋나면 거절됩니다. VCF 9.0.2의 SDDC Manager 9.0.2.0100은 2026-07-28 출시이고, VCF 9.1.0.0000은 2026-05-11 출시라 지원되지 않습니다. VCF 5.2.4와 vSphere 8.0 Update 3j도 2026-05-27 출시라 9.1.0.0000으로 올리지 못합니다. 운영 승인은 Upgrade Planning Tool과 상호운용 행렬을 같은 기록에 남깁니다.

## 지금 결정할 것

- 이번 창에서 플릿과 관리 도메인만 올릴지, 워크로드 도메인까지 넣을지
- 출발이 5.2 미만인지, 5.2.x인지, 9.0.x인지
- 현재 구성 요소 출시일이 9.1.0.0000보다 이후라 대상 패치를 다시 고를지
- 수명주기 작업을 업그레이드 후 VCF Operations로 옮길지. SDDC Manager UI는 폐기 예정
- vSphere Foundation 9.1 경로와 VCF 9.1 경로를 같은 표에 둘지

## 의사결정 기준

### 관리 도메인과 워크로드를 한 줄로 합치지 않습니다

업그레이드 문서는 관리 구성 요소와 관리 도메인을 의무로 두고, 워크로드는 해당 인스턴스의 관리 도메인을 올린 뒤에 언제든 할 수 있다고 적습니다. 호스트만 먼저 9.1로 올린다는 가정을 승인 조건에 넣지 않습니다.

### 출발 버전에 따라 표가 갈립니다

5.2.x는 Aria Operations를 VCF Operations 9.1로 올리는 일부터 시작합니다. Aria Suite Lifecycle은 9.1 업그레이드가 없고, Identity Manager 3.3.x Day-N을 위해 남깁니다. 9.0.x는 VCF Operations 업그레이드 중에 fleet management 장비가 해제됩니다. 이 장비가 맡던 인증서와 비밀번호는 나머지 구성 요소를 9.1로 올리기 전에는 관리할 수 없습니다.

### 이후 날짜 패치를 9.1.0.0000에 얹지 않습니다

정방향 제한은 대상 버전이 현재 버전보다 나중에 나와야 한다고 적습니다. 2026-05 이후 나온 5.2.4나 9.0.2 패치를 2026-05-11의 9.1.0.0000으로 되돌리듯 올리지 않습니다. 대상 BOM은 Upgrade Planning Tool과 상호운용 행렬로 다시 고릅니다.

### vSphere 9.1을 단독 노트로 보지 않습니다

vSphere 9.1 색인은 릴리스 노트를 VCF 9.1에서 읽으라고 적습니다. 단독 vSphere 8에서 시작하는 경로는 별도 시나리오로 안내됩니다. VCF와 vSphere Foundation을 같은 의무 순서로 적지 않습니다.

## 실무 체크리스트

1. 출발 버전을 5.2 미만, 5.2.x, 9.0.x, 단독 vSphere로 표시합니다.
2. 플릿 관리 구성 요소와 관리 도메인, 워크로드 도메인을 나눕니다.
3. 각 구성 요소 출시일을 9.1.0.0000과 이후 패치에 대조합니다.
4. Upgrade Planning Tool 시나리오와 상호운용 행렬을 변경 요청서에 붙입니다.
5. 5.2.x면 Aria Suite Lifecycle과 Identity Manager 잔존 범위를 적습니다.
6. 9.0.x면 fleet management 해제 전에 올릴 구성 요소 순서를 적습니다.
7. 업그레이드 후 수명주기 UI를 VCF Operations로 옮길 담당자를 지정합니다.
8. 워크로드 도메인 Day-N 일정과 승인자를 따로 남깁니다.

## 제외 범위

- VMSA-2026-0006 vCenter와 ESX 보안 advisory의 재작성
- VMware와 Nutanix 평가 행렬의 확장. 그 문서는 비공개 검토로 유지한다
- 특정 하이퍼바이저의 우열, 가격, 성능 비교
- 업그레이드가 무중단이거나 라이선스가 자동으로 맞다는 보장
- 고객별 BOM, 라이선스 키, 계정, 웹훅의 공개
