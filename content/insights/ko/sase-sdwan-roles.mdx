해외지사 환경에서는 “SASE를 도입할 것인가, SD-WAN을 도입할 것인가”보다 먼저 연결과 보안의 문제를 분리해야 합니다. SD-WAN은 여러 회선의 경로·품질 제어를 다루고, SASE는 사용자와 애플리케이션 접근에 필요한 보안 통제를 클라우드 경계에서 제공하는 접근입니다. 실제 환경에서는 두 범위가 함께 검토될 수 있지만, **문제와 책임은 한 표에서 분리**해야 합니다.

## 지점별로 확인할 판단표

| 항목 | 질문 | 검증 결과 |
| --- | --- | --- |
| 회선 품질 | 지역별 인터넷·전용회선의 지연·손실·장애는 어떤가 | 경로 우선순위 |
| 애플리케이션 | SaaS·데이터센터·클라우드 중 어디로 가는가 | 트래픽 흐름 지도 |
| 사용자 접근 | 지점 사용자·외부 인력의 권한은 어떻게 다른가 | 접근 정책 |
| 장애 대응 | 회선·보안 정책·인증 장애를 누가 구분하는가 | 운영 책임표 |
| 로그 | 어느 시스템이 어떤 이벤트를 보관·분석하는가 | 관제·감사 범위 |

## PoC에서 확인할 것

1. 대표 지점과 대표 애플리케이션을 하나씩 고릅니다.
2. 정상·회선 장애·정책 변경·인증 실패 시의 경로와 사용자 경험을 확인합니다.
3. 로컬 인터넷 분기, 데이터센터 접근, SaaS 접근을 같은 기준으로 기록합니다.
4. 장애 알림을 받은 운영자가 원인을 식별하고 조치할 수 있는지 확인합니다.

## 역할을 섞으면 생기는 오류

경로 품질 문제를 보안 제품 교체로만 해결하려 하거나, 사용자 접근 정책을 회선 설정으로만 해결하려 하면 책임 경계가 흐려집니다. NIST의 최신 구현 가이드는 SASE를 포함한 여러 Zero Trust 접근을 예시로 제시하며, 단일 정답이 아니라 조직의 접근 제어 과정과 정책을 지속적으로 개선하는 방식으로 설명합니다. [NIST SP 1800-35](https://csrc.nist.gov/pubs/sp/1800/35/final)

## 이 단계의 산출물

지점별 트래픽 지도, 애플리케이션 경로 표, 사용자 접근 정책, 장애·로그 책임표를 남깁니다. 이 결과가 있어야 SASE·글로벌 연결에서 어떤 지점부터 검증할지와 기존 회선을 유지할 범위를 함께 결정할 수 있습니다.

## 함께 확인할 항목

- 지역별 인터넷과 전용회선 품질
- 업무 애플리케이션의 위치와 지연 민감도
- 사용자, 장치와 지점별 보안정책
- 장애 시 우회와 정책 일관성
- 현지 지원, 로그와 운영 책임

두 접근을 결합할 때는 제품 기능표보다 실제 트래픽 경로와 운영 절차를 기준으로 PoC를 설계합니다.
