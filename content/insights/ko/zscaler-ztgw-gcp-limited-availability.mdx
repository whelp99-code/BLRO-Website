## 한눈에 보기

Zscaler 제품 블로그 2026-08-12는 Zero Trust Gateway for Google Cloud가 Google Cloud Network Security Integration과 Security Profiles로 트래픽을 검사로 보낸다고 적습니다. 도움말의 추가 페이지와 분석 페이지는 GCP 게이트웨이가 Limited Availability이며 켜려면 Support에 연락하라고 적습니다.

- 결정: Limited Availability를 파일럿으로 둘지, 생산 기본 경로로 보지 않을지
- 전제: 추가는 리전을 하나 고르고 만든 뒤 바꿀 수 없으며, 가용 영역은 최소 두 곳을 골라야 한다
- NSI: 블로그는 Security Profiles와 레이블·네트워크 태그를 정책 메타데이터로 쓴다고 적는다
- 범위: Prisma SD-WAN ION 양자내성 글의 재작성이 아니다

## 문제 상황

GCP 워크로드에 Zero Trust를 붙인다고 보고하면, 마케팅의 관리형 게이트웨이와 Limited Availability 콘솔 절차가 한 승인에 섞입니다.

추가 페이지는 Infrastructure Connectors Cloud Zero Trust Gateway -- GCP에서 게이트웨이를 만든다고 적습니다. 리전은 배포 후 수정할 수 없고, 가용 영역은 최소 두 곳입니다. IAM principal 유형은 User, Group, Service Account입니다. 연결 요청은 그 principal에 연결된 intercept endpoint group에서 온 것만 허용한다고 적습니다.

분석 페이지도 Limited Availability와 Support 연락을 반복합니다. Intercept Deployment Group은 VPC 트래픽을 가로채 검사하는 GCP 리소스이고, Intercept Endpoint Group은 프로젝트 전역에서 Zscaler 관리 서비스에 접근하는 리소스라고 적습니다. 상태는 Healthy, Unhealthy, Not Available을 두고, 가용 영역 백엔드는 Healthy, Unhealthy, Degraded를 둡니다.

블로그는 NSI와 Security Profiles, Profile Groups로 트래픽을 투명하게 Zscaler로 보낸다고 적습니다. 애플리케이션 변경이나 수동 터널, 복잡한 라우트 개편 없이 레이블과 네트워크 태그를 정책 메타데이터로 쓴다고 적습니다. 절감액 숫자는 이 글에 옮기지 않습니다. About Google Cloud Platform Zero Trust Gateways 페이지는 이 확인에서 JavaScript 셸만 있어 본문 한도를 출처로 쓰지 않았습니다.

## 지금 결정할 것

- Limited Availability를 Support로 연 파일럿으로 둘지, 생산 표준으로 보지 않을지
- 리전과 최소 두 가용 영역을 지금 고정할지. 리전은 생성 후 바꿀 수 없다
- NSI Security Profiles로 보낼 트래픽과, 보내지 않을 VPC를 가를지
- IAM principal을 User, Group, Service Account 중 무엇으로 묶을지
- Prisma SD-WAN이나 다른 SASE 글과 이 결정을 섞지 않을지

## 의사결정 기준

### Limited Availability와 블로그 소개를 같은 일반 공급으로 보지 않습니다

추가 페이지와 분석 페이지는 LA이며 Support에 연락하라고 적습니다. 블로그 날짜 2026-08-12와 관리형 서비스 소개를 GA 승인으로 옮기지 않습니다.

### 리전과 가용 영역은 생성 전제입니다

추가는 리전을 하나 고르고 이후 수정할 수 없다고 적습니다. 가용 영역은 최소 두 곳입니다. 한 리전 파일럿을 다중 리전 생산처럼 보고하지 않습니다.

### NSI 연동과 intercept 리소스를 한 스위치로 보지 않습니다

블로그는 NSI Security Profiles와 레이블·네트워크 태그 메타데이터를 적습니다. 분석 페이지는 Intercept Deployment Group과 Intercept Endpoint Group을 운영 화면에 둡니다. 프로필을 켰다고 intercept 그룹과 IAM principal이 맞다고 보지 않습니다.

### 금액 절감과 다른 SASE 글을 근거로 쓰지 않습니다

블로그의 비용 절감 숫자는 인용하지 않습니다. Prisma SD-WAN ION 양자내성이나 Cisco Secure Access 글과 이 게이트웨이 결정을 한 표에 넣지 않습니다.

## 실무 체크리스트

1. Support로 GCP Zero Trust Gateway LA를 열 대상 프로젝트와 계정인지 확인합니다.
2. 배포할 리전과 최소 두 가용 영역을 생성 전에 고정합니다.
3. IAM principal 유형과 VPC, intercept endpoint group 연결을 기록합니다.
4. NSI Security Profiles로 보낼 워크로드와 보내지 않을 워크로드를 가릅니다.
5. 레이블과 네트워크 태그를 정책 메타데이터로 쓸지 보안 정책 소유자에게 확인합니다.
6. 생성 후 분석 화면의 Internet, Local Egress, Private Applications 상태 확인 책임을 정합니다.
7. 블로그 절감 숫자를 내부 투자 근거로 쓰지 않는지 검토합니다.
8. Prisma SD-WAN이나 다른 SASE 초안과 중복 승인하지 않습니다.
