## 한눈에 보기

- **맞는 대상:** 온프레미스 서버, 쿠버네티스, 하이브리드처럼 TLS를 고객 관리 인프라에서 종료하는 환경
- **맞지 않는 대상:** ELB, CloudFront, API Gateway에 인증서를 연결하고 ACM이 키와 갱신을 관리해야 하는 환경
- **핵심 결정:** 사설 키 소유자, 도메인 발급 권한, EAB 배포, 갱신 실패 관측 책임
- **운영 조건:** ACME 인증서는 45일 유효하며, 갱신과 폐기는 ACME 클라이언트가 담당

## 이 글의 범위

AWS의 ACME 지원은 인증서를 자동으로 발급하는 기능이지만, 자동화 도입의 성패는 인증서 요청 도구가 아니라 권한과 책임 경계에 달려 있습니다. 이 글은 AWS 공지·운영 문서뿐 아니라 ACME 표준, 장애 조치, 감사 로그까지 확인해 고객 관리 인프라에서 필요한 판단 기준을 정리합니다.

## 먼저 나눌 두 가지 경로

| TLS 종료 위치 | 권장 검토 경로 | 이유 |
| --- | --- | --- |
| ELB, CloudFront, API Gateway | `RequestCertificate` | ACM이 사설 키와 갱신을 관리하는 통합 서비스 경로 |
| 온프레미스 웹 서버, 리버스 프록시, 쿠버네티스 ingress | ACME endpoint | ACME 클라이언트가 키를 보관하고 인증서 수명주기를 실행하는 고객 관리 인프라 경로 |

ACME 발급 인증서는 사설 키를 ACME 클라이언트가 생성·보관하며 ACM은 키를 보지 않습니다. 따라서 AWS 통합 서비스에 바인딩할 수 없고, ACM managed renewal도 적용되지 않습니다.

## 지금 결정할 4가지

### 1. 사설 키의 소유자와 보관 위치

ACME에서는 애플리케이션 운영 측이 키를 생성하고 보관합니다. 키 백업, 교체, 폐기와 접근 권한도 같은 운영 경계에 둡니다. 키를 AWS 통합 서비스가 관리해야 한다면 ACME가 아니라 `RequestCertificate` 경로를 검토합니다.

### 2. 누가 어떤 도메인을 발급할 수 있는가

AWS ACM은 PKI 관리자가 endpoint를 만들고 사전 도메인 검증과 EAB 자격 증명을 관리하는 control plane, 애플리케이션 소유자가 인증서를 요청하고 갱신하는 data plane을 분리합니다. RFC 8555의 External Account Binding도 ACME 계정을 기존 비-ACME 계정과 연결하는 방식입니다. 따라서 EAB는 배포 편의 항목이 아니라 발급 권한 통제 항목으로 다룹니다.

### 3. 45일 수명주기를 운영할 수 있는가

AWS 공지 기준으로 ACM ACME 인증서는 45일 유효합니다. 갱신은 ACME 클라이언트가 새 인증서를 요청하는 방식이며 ACM managed renewal은 적용되지 않습니다. 수동 갱신 절차가 남아 있으면 자동화 전환이 아니라 새로운 만료 위험이 됩니다.

### 4. 실패와 발급 이력을 어디서 볼 것인가

ACM은 endpoint 콘솔과 CloudWatch 지표로 발급을 모니터링할 수 있습니다. 중앙 감사가 필요하면 CloudTrail의 ACM ACME endpoint 데이터 이벤트를 별도로 켜야 합니다. 이 데이터 이벤트는 기본 수집되지 않으므로, 발급·조회·폐기 이력을 감사 범위에 넣으려면 trail 또는 event data store 구성을 확인합니다.

## 운영 설계 기준

### 권한은 endpoint 단위로 분리합니다

환경·도메인·와일드카드 정책을 endpoint와 domain validation에 반영합니다. PKI 관리자는 endpoint, 사전 승인 도메인, EAB와 IAM을 관리하고 애플리케이션 운영자는 받은 EAB로 필요한 도메인만 요청·갱신합니다.

### 갱신 실패는 인증서 만료 전에 잡습니다

AWS는 발급 대기 시간이 길어질 수 있어 ACME 클라이언트의 issuance timeout을 최소 600초로 안내합니다. 만료 일자만 보는 대신 endpoint의 발급 실패, 도메인 validation CNAME, 클라이언트 갱신 작업, 배포 반영 상태를 함께 점검합니다.

### 감사 로그는 선택적으로 활성화합니다

CloudTrail은 `NewAccount`, `NewOrder`, `FinalizeOrder`, `GetCertificate`, `RevokeCertificate` 등 ACME 프로토콜 작업을 데이터 이벤트로 기록할 수 있습니다. 발급 책임 추적이 요구되는 환경에서는 수집 범위와 보존 정책을 운영 기준에 포함합니다.

## 실행 체크리스트

1. TLS 종료 자산을 `AWS 통합 서비스`와 `고객 관리 인프라`로 나눕니다.
2. 도메인별 소유자, 사설 키 보관 위치, 갱신 실행 주체를 자산 목록에 연결합니다.
3. PKI 관리자와 애플리케이션 운영자의 endpoint·domain validation·EAB·IAM 책임을 분리합니다.
4. 환경별 도메인 범위와 와일드카드 허용 여부를 사전 승인 정책으로 문서화합니다.
5. 사용하는 ACME 클라이언트가 600초 이상의 발급 대기 시간을 설정할 수 있는지 확인합니다.
6. 발급 실패, validation CNAME 변경, 갱신 작업 실패, 배포 미반영을 운영 알람과 runbook에 연결합니다.
7. CloudTrail 데이터 이벤트가 필요한 감사 범위라면 대상 endpoint와 보존 정책을 명시적으로 설정합니다.
8. 키 분실, EAB 노출, 갱신 실패, 인증서 폐기 시의 담당자와 복구 절차를 검토합니다.
