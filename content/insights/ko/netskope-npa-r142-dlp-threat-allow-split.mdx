## 한눈에 보기

Netskope Real-time Protection for Private Apps 문서는 Beginning in R142, NPA DLP and Threat Protection policies only perform inspection — they no longer grant access라고 적습니다. NPA는 기본적으로 트래픽을 허용하지 않습니다.

- 결정: R142가 테넌트에 도달하기 전에, DLP·Threat로만 열리던 사설앱마다 전용 Private App Access Allow 정책을 추가할지
- 전제: 검사하는 private app마다 Real-time Protection Private App Access Allow가 따로 필요합니다. NPA DLP·Threat 자격이 없으면 해당 검사 정책을 제거합니다
- 운영 순서: R142 전에 Allow와 검사 정책을 함께 만들고, Steering Configuration에 Private App Segments를 켝니다
- 범위: R142 이후에는 Access와 DLP·Threat 정책 순서가 더 이상 중요하지 않다고 문서가 적습니다

## 문제 상황

Private App Segments는 기본적으로 steer되지 않아 사용자에게 열리지 않습니다. Steering profile에 private apps를 넣고, discovery가 없으면 matching real-time policy가 있어야 접근과 로그가 생깁니다.

R142 이전에는 DLP·Threat 프로필이 달린 규칙 배치와 Access 규칙 순서가 중요했습니다. R142부터는 DLP·Threat 정책이 접근을 주지 않고 검사만 합니다. 같은 앱·사용자에 대한 Allow 정책이 없으면 일시적으로 연결이 끊길 수 있다고 경고합니다. 자격이 없으면 Allow를 만들기보다 해당 DLP·Threat 정책을 제거하라고 적습니다.

Steering 문서는 OUs·User Groups를 접근을 주는 Real-time Protection policy에 지정한다고 적습니다. Settings > Security Cloud Platform > Steering Configuration에서 Private App Segments를 켝니다.

## 지금 결정할 것

- 테넌트에 R142가 언제 적용되는지 변경창을 잡을지
- DLP 또는 Threat 프로필만 있는 Private App Segment 목록을 먼저 뽑을지
- 각 앱에 Enabled Private App Access Allow를 추가할지
- NPA DLP·Threat 비자격이면 검사 정책을 삭제하는 쪽으로 갈지
- Steering Configuration의 Private App Segments와 Allow 대상 OU·Group을 같은 승인으로 묾을지

## 의사결정 기준

### 검사 정책과 Allow 정책을 분리합니다

R142 이후 DLP·Threat 정책은 inspection only입니다. Action=Allow인 Private App Access 정책이 같은 사용자·앱에 Enabled로 있어야 접근이 유지됩니다. 검사 프로필만 남겨 두고 Allow를 생략하지 않습니다.

### 자격 있음과 자격 없음을 가릅니다

자격이 있으면 Allow를 추가합니다. 자격이 없으면 Allow를 만들기보다 DLP·Threat 정책을 제거합니다. 두 경로를 한 변경으로 섞지 않습니다.

### R142 전·후 정책 순서를 나눍니다

R142 전에는 Access 규칙을 DLP·Threat 뒤에 두라고 적습니다. From R142 this order is no longer important라고 문서가 적습니다. 순서 정리만으로 R142 대비가 끝났다고 보지 않고, Allow 존재 여부를 먼저 봅니다.

### Steering과 Real-time Allow 대상 사용자를 맞춥니다

Steering Configuration의 OU·User Group과 Allow 정책 Source의 Users·OU·Groups가 어긋나면 steer만 되고 접근이 거절되거나, 그 반대가 됩니다. Steering과 Allow를 같은 사용자 집합으로 검토합니다.

## 실무 체크리스트

1. R142 적용 예정일을 테넌트 변경 달력에 적습니다.
2. Policies > Real-time Protection에서 Private App Segment에 DLP 또는 Threat 프로필이 있는 규칙을 목록화합니다.
3. 같은 앱·사용자에 Action=Allow인 Private App Access 정책이 Enabled인지 확인합니다.
4. Allow가 없으면 R142 전에 New policy > Private App Access로 Allow를 만듭니다.
5. NPA DLP·Threat 자격이 없으면 해당 검사 정책 제거를 승인합니다.
6. Settings > Security Cloud Platform > Steering Configuration에서 Private App Segments를 켝니다.
7. Allow Source의 OU·User Group과 Steering 대상을 대조합니다.
8. 주간 점검: DLP·Threat가 있는 모든 Private App Segment에 Enabled Allow가 있으면 PASS로 기록합니다.
