## 한눈에 보기

AWS Backup은 2026-08-06에 S3 복구 지점용 접근점을 발표했습니다. 표준 S3 읽기 API로 백업을 바로 읽고, 접근점이 살아 있는 동안 해당 복구 지점 삭제가 막힙니다.

- 결정: 대상 파일을 복원할지, 읽기 전용 접근점으로 볼지, 접근점을 언제 지울지
- 전제: 쓰기·삭제·멀티파트 업로드는 지원하지 않고 S3 복구 지점에만 해당한다고 운영 문서가 적는다
- 불일치: What's New는 접근점이 켜져 있으면 복구 지점 삭제를 막는다고 적고, 운영 문서는 수명 주기 중지와 수동 삭제 차단, S3에서 직접 지우면 EXPIRED 잔존을 나눈다
- 범위: EKS 논리 에어갭 볼트 설계가 아니라 S3 백업의 읽기 경로

## 문제 상황

일부 객체만 확인하려고 버킷 전체를 복원하면 시간이 걸립니다. 접근점을 켜면 읽기는 빨라지지만, 그 복구 지점은 지워지지 않습니다.

What's New는 GetObject, HeadObject, ListObjectsV2로 스냅샷과 연속 복구 지점을 읽고, 표준 볼트와 논리 에어갭 볼트, RAM 공유와 다자 승인 경로를 포함한다고 적습니다. 일부 리전에서만 쓸 수 있다고 적습니다.

운영 문서는 접근점이 있으면 예약된 수명 주기 전환을 멈추고 DeleteRecoveryPoint를 거절한다고 적습니다. delete-after-days는 바꿀 수 있지만 모든 접근점을 지운 뒤에야 삭제가 적용됩니다. 접근점에는 삭제 예정일이 없고 수동으로 지워야 합니다. S3 API로 접근점만 지우면 Backup 쪽은 EXPIRED로 남고 수명 주기 보호가 유지됩니다.

연속 복구 지점은 만들 때 AccessPointInTime이 보존 창 안에 있어야 하고, 만든 뒤에는 그 시각 데이터가 창 밖으로 나가도 남습니다. 계정마다 복구 지점당 접근점은 상태와 관계없이 최대 5개입니다.

## 지금 결정할 것

- 대상이 부분 읽기인지, 버킷 단위 복원인지
- 접근점을 감사·포렌식 창에만 둘지, 상시로 둘지
- 논리 에어갭 볼트에서 소유 계정만 만들게 할지, RAM 공유 계정에도 허용할지
- 접근점을 누가 지워 수명 주기를 다시 살릴지
- 일부 리전 제한을 수용할지

## 의사결정 기준

### 읽기 접근점과 복원 작업을 같은 복구로 보지 않습니다

접근점은 읽기만 제공합니다. 운영 문서는 PutObject, DeleteObject, CopyObject를 지원하지 않는다고 적습니다. 객체를 다른 버킷에 되살리는 작업은 기존 복원 경로입니다. 파일 확인과 운영 복구를 한 승인으로 묶지 않습니다.

### 삭제 보호 문장은 운영 문서의 수명 주기 절을 엽니다

What's New는 접근점이 활성일 때 복구 지점 삭제를 막는다고 적습니다. 운영 문서는 수명 주기 중지, 수동 삭제 차단, 보존일 변경은 가능하나 집행은 접근점 삭제 후라고 적습니다. S3에서 직접 지우면 보호가 남는다고 적습니다. 운영 기준은 Developer Guide의 Recovery point lifecycle protection입니다.

### 논리 에어갭 읽기와 EKS 에어갭 설계를 섞지 않습니다

접근점은 S3 복구 지점에만 있습니다. 논리 에어갭 볼트의 읽기는 RAM 권한과 볼트 정책으로 제한할 수 있습니다. 이 글은 EKS 워크로드를 에어갭 볼트에 넣는 설계를 다시 쓰지 않습니다.

### 연속 복구 시각과 보존 창을 한 값으로 두지 않습니다

AccessPointInTime은 생성 시점의 보존 창 안에 있어야 합니다. 접근점이 남아 있으면 그 시각 데이터는 창이 지나도 유지됩니다. 감사 창을 끝내지 않으면 보존 정책이 기대한 시점에 줄지 않을 수 있습니다.

## 실무 체크리스트

1. 대상이 스냅샷인지 연속 복구 지점인지, 어느 볼트인지 적습니다.
2. 부분 읽기인지 전체 복원인지 나눕니다.
3. 리전이 What's New의 선택 리전에 있는지 확인합니다.
4. 접근점 이름을 같은 계정·리전의 S3 접근점과 겹치지 않게 정합니다.
5. 연속 복구면 AccessPointInTime을 생성 창 안으로 적습니다.
6. 접근점 정책과 계정 Block Public Access를 확인합니다.
7. 수명 주기 재개를 위해 삭제 책임자와 기한을 정합니다.
8. S3 콘솔이 아니라 DeleteBackupAccessPoint로 지운다고 절차에 적습니다.
