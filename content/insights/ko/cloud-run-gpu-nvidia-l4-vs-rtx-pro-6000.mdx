## 한눈에 보기

이번 주에는 Cloud Run Services에서 대상 서비스를 연 뒤 Containers 탭, 또는 gcloud run services describe에서 GPU type과 zonal redundancy, CPU·memory 하한이 의도 값인지 확인한다.

- 결정: GPU를 nvidia-l4로 둘지 nvidia-rtx-pro-6000으로 올릴지, zonal redundancy와 함께 고정할지
- 전제: nvidia-rtx-pro-6000은 최소 20 CPU·80 GiB, nvidia-l4는 최소 4 CPU·16 GiB
- 쿼터: 리전 첫 배포 시 l4는 GPU 3개, rtx-pro-6000은 3000 milliGPU, 둘 다 zonal redundancy off
- 범위: Agent Identity Registry 글이 아니라 서비스 GPU 타입과 zonal redundancy

## 문제 상황

GPU를 켰다고 보고하면, 타입 미지정, zonal redundancy 기본값, CPU·memory 하한 미달이 한 완료로 섞입니다.

GPU support for services는 NVIDIA RTX PRO 6000 Blackwell 96 GB VRAM과 NVIDIA L4 24 GB VRAM을 적습니다. 타입 값은 nvidia-rtx-pro-6000과 nvidia-l4입니다. 인스턴스당 GPU는 하나입니다. 콘솔은 GPU 확인란을 켠 뒤 GPU type과 Number of GPUs를 고릅니다. 새 서비스는 기본적으로 zonal redundancy가 켜집니다. 끄려면 No zonal redundancy, 켜려면 Zonal redundancy를 고릅니다.

gcloud는 gcloud run deploy에 --gpu를 쓰고, 갱신은 gcloud run services update에 --gpu, --gpu-type, --no-gpu-zonal-redundancy 또는 --gpu-zonal-redundancy를 둡니다. --gpu만 있고 --gpu-type이 없으면 타입을 고정한 것이 아닙니다.

nvidia-rtx-pro-6000 쿼터는 milliGPU입니다. 리전 첫 배포는 zonal redundancy off로 3000 milliGPU, GPU 3개와 같다고 적습니다. nvidia-l4 첫 사용은 zonal redundancy off로 GPU 3개입니다. Quotas 페이지는 새 프로젝트가 L4 서비스를 만들면 NvidiaL4GpuAllocNoZonalRedundancyPerProjectRegion 3이 자동으로 주어진다고 적습니다.

지원 리전 목록에 한국 리전은 없습니다. L4는 asia-southeast1, asia-south1 초대, europe-west1, europe-west4, us-central1, us-east4입니다. RTX PRO 6000은 asia-southeast1, asia-south2, europe-west4, us-central1입니다. 리전을 고르지 않고 타입만 정하지 않습니다.

## 지금 결정할 것

- 대상 서비스 GPU를 nvidia-l4로 둘지 nvidia-rtx-pro-6000으로 올릴지
- zonal redundancy를 켤지, No zonal redundancy로 둘지
- RTX PRO 6000이면 CPU 20·memory 80Gi 이상인지, L4면 CPU 4·memory 16Gi 이상인지
- 리전이 해당 GPU 지원 목록에 있는지
- 최대 인스턴스가 프로젝트·리전 GPU 쿼터 아래인지

## 의사결정 기준

### GPU 타입과 zonal redundancy를 한 스위치로 보지 않습니다

타입은 accelerator 값입니다. zonal redundancy는 예비 용량과 가격이 갈립니다. 기본은 켜짐입니다. 콘솔에서 No zonal redundancy를 고르거나 --no-gpu-zonal-redundancy를 넣지 않으면 켠 것입니다. 타입만 보고 이중화를 정했다고 보지 않습니다.

### 하한 미달을 배포 완료로 보지 않습니다

nvidia-rtx-pro-6000은 최소 20 CPU와 80 GiB입니다. nvidia-l4는 최소 4 CPU와 16 GiB이며 8 CPU·32 GiB를 권장합니다. 타입을 올리고 CPU·memory가 하한 아래면 문서 전제를 벗어난 구성입니다. instance-based billing이 필요하다고 적습니다.

### 첫 사용 자동 쿼터와 증설 요청을 한 용량으로 보지 않습니다

l4 3 GPU와 rtx-pro-6000 3000 milliGPU는 zonal redundancy off 첫 배포 자동 부여입니다. 그 이상 또는 zonal redundancy on은 쿼터 요청입니다. Quotas 페이지의 GPU instance 한도 기본값은 0이고 증가 가능이라고 적습니다. describe에 GPU가 보여도 쿼터 증설이 끝난 것은 아닙니다.

### 모델 적재 권고와 GPU 타입 결정을 한 승인으로 묶지 않습니다

gpu-best-practices는 모델 위치, 동시성, 시작 프로브를 다룹니다. 이 초안은 타입과 zonal redundancy를 먼저 고정합니다. 모델 적재 튜닝은 별도 과제입니다.

## 실무 체크리스트

1. 대상 Cloud Run 서비스와 리전을 기록합니다. 지원 목록에 없는 리전이면 이번 창에서 제외합니다.
2. GPU를 nvidia-l4로 둘지 nvidia-rtx-pro-6000으로 올릴지 승인 조건에 적습니다.
3. 콘솔 Containers 탭에서 GPU type, Number of GPUs, No zonal redundancy 또는 Zonal redundancy를 읽습니다.
4. CLI는 gcloud run services describe로 같은 값을 확인합니다. 갱신은 gcloud run services update --gpu --gpu-type입니다.
5. nvidia-rtx-pro-6000이면 CPU 20 이상, memory 80Gi 이상인지 대조합니다. nvidia-l4면 CPU 4 이상, memory 16Gi 이상인지 대조합니다.
6. 과금이 instance-based billing인지 확인합니다.
7. 최대 인스턴스가 프로젝트·리전 GPU 쿼터를 넘지 않는지 적습니다.
8. 「이번 주 운영 확인」 PASS = 서비스에 선택한 GPU 타입과 zonal redundancy가 의도대로이고 RTX PRO 6000이면 CPU 20·80 GiB 이상이다. FAIL = 타입 또는 zonal redundancy가 없거나 RTX PRO 6000 최소 20 CPU·80 GiB와 불일치한다.
