## 한눈에 보기

OpenShift Virtualization 릴리스 노트는 4.20이 OpenShift Container Platform 4.20 클러스터에서만 지원된다고 적습니다. 확인일 기준 최신 안정 릴리스는 4.20.24입니다.

- 결정: 현재 마이너의 최신 z-stream으로 갈지, 4.19에서 4.20으로 마이너를 올릴지
- 전제: 중간 z-stream은 건너뛸 수 있으나, 다음 마이너 전에 현재 마이너의 최신 z-stream으로 먼저 올려야 한다
- 4.19에서 4.20: 업그레이드를 시작하기 전에 wasp-agent를 제거해야 한다
- 범위: VMware VCF 정방향 업그레이드나 Hyper-V GPU 글이 아니라 OpenShift Virtualization 경로

## 문제 상황

가상화 Operator를 버전 번호만으로 올리면, 같은 마이너 안의 z-stream 건너뛰기와 4.19에서 4.20으로 가는 마이너 업그레이드가 한 변경 창에 섞입니다.

릴리스 노트는 중간 z-stream을 건너뛰고 이후 z-stream으로 바로 올릴 수 있다고 적습니다. 다만 다음 마이너로 가기 전에 현재 마이너의 최신 z-stream으로 먼저 업데이트하라고 못 박습니다. 최신 OpenShift Virtualization z-stream을 쓰려면 OpenShift Container Platform을 먼저 최신으로 올려야 한다고도 적습니다.

업데이트 장은 각 마이너가 대응하는 OpenShift Container Platform에서만 지원된다고 반복합니다. OpenShift Virtualization 4.20은 OpenShift Container Platform 4.20에서 실행해야 합니다. 다음 마이너 OpenShift Virtualization은 OpenShift Container Platform을 먼저 올린 뒤에만 쓸 수 있습니다. 같은 장은 Control Plane Only 설명에서, 현재 마이너의 최신 z-stream으로 중간 z-stream 없이 바로 갈 수 있다고 다시 적습니다.

4.19에서 4.20으로 올리는 알려진 문제는 wasp-agent를 제거한 뒤에만 업그레이드를 시작하라고 적습니다. 설치 후 구성 장은 wasp-agent가 메모리 오버커밋용이며, 제거할 때 HyperConverged의 higherWorkloadDensity를 빼고 MachineConfig 90-worker-swap과 KubeletConfig custom-config를 지운 뒤 워커가 맞춰질 때까지 기다리라고 적습니다.

## 지금 결정할 것

- 대상이 4.20 안의 z-stream인지, 4.19에서 4.20으로 가는 마이너인지
- 현재 마이너의 최신 z-stream을 먼저 맞출지
- 4.19면 wasp-agent와 스왑 오버커밋을 제거한 뒤에 올릴지
- 구독 스킬을 stable과 Automatic으로 둘지, Manual 승인을 유지할지
- hostpath provisioner VM이 클러스터 업데이트를 막을 수 있는지를 변경 창에 넣을지

## 의사결정 기준

### 같은 마이너 z-stream과 다음 마이너를 한 경로로 보지 않습니다

릴리스 노트와 업데이트 장은 중간 z-stream 건너뛰기를 허용합니다. 다음 마이너로 가기 전에 현재 마이너의 최신 z-stream이 전제입니다. 4.20.24가 보인다고 해서 4.19 클러스터에 바로 적용한다고 쓰지 않습니다.

### OpenShift Container Platform 버전을 먼저 맞춥니다

OpenShift Virtualization 4.20은 OpenShift Container Platform 4.20에서만 지원됩니다. 업데이트 장은 다음 마이너 OpenShift Virtualization이 OpenShift Container Platform 다음 마이너 이후에만 열린다고 적습니다. Operator만 올리고 클러스터 마이너를 남겨 두지 않습니다.

### 4.19에서 4.20은 wasp-agent 제거가 전제입니다

릴리스 노트는 4.19에서 4.20으로 올리기 전에 wasp-agent를 제거하라고 적습니다. 설치 후 구성 장은 메모리 오버커밋을 더 쓰지 않을 때의 제거 절차를 적습니다. 오버커밋을 4.20 이후에도 다시 쓸지는 업그레이드와 별도 결정입니다. 제거하지 않고 마이너 창을 열지 않습니다.

### Manual 승인과 지원 가능 상태를 같은 승인으로 보지 않습니다

업데이트 장은 stable 채널과 Automatic 승인을 권합니다. Manual이면 대기 중인 업데이트를 모두 승인해야 하고, OpenShift Container Platform과 OpenShift Virtualization이 어긋나면 클러스터가 미지원이 된다고 적습니다. Automatic을 끈 채로 마이너 창을 열지 말고, 승인 책임을 기록합니다.

## 실무 체크리스트

1. 현재 OpenShift Container Platform과 OpenShift Virtualization 마이너, z-stream을 기록합니다.
2. 목표가 4.20 최신 z-stream인지, 4.19에서 4.20인지 나눕니다.
3. 4.20 z-stream이면 현재 마이너의 최신 z-stream으로 먼저 가는지 확인합니다.
4. 4.19에서 4.20이면 wasp-agent, higherWorkloadDensity, 90-worker-swap, custom-config 잔존을 확인합니다.
5. 구독 채널과 승인 전략을 stable, Automatic, Manual 중 무엇으로 둘지 적습니다.
6. hostpath provisioner VM과 live migration 가능 여부를 변경 창에 남깁니다.
7. 업데이트 후 CSV PHASE와 HyperConverged 조건을 누가 확인하는지 정합니다.
8. 4.20 이후 메모리 오버커밋을 다시 켤지는 업그레이드와 분리해 승인합니다.
