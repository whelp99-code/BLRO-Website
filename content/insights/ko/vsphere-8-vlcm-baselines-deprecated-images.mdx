## 한눈에 보기

vSphere 8.0 Release Notes는 vSphere Lifecycle Manager baselines and baseline groups 관리가 8.0에서는 지원되지만 이후 릴리스에서 지원이 사라진다고 적습니다. vSphere 9.1 문서는 Baseline support was deprecated in vSphere 8.0 and removed in 9.0라고 적습니다.

- 결정: 아직 baseline으로 관리하는 클러스터를, 미래 ESX 메이저 업그레이드에 의존하기 전에 이미지로 되돌릴 수 없게 전환할지
- 전제: 이미지로 바꾸면 그 클러스터에서는 baseline으로 되돌릴 수 없다. 호스트를 baseline 클러스터로 옮기는 것만 남는다
- 운영: vSphere 9.0에서 최신 ESX 업그레이드는 이미지로만 가능하다. 8.x 패치는 baseline으로 남을 수 있다
- 범위: NVIDIA 인증이나 vSAN Max 유형 글의 재작성이 아니다. baseline과 이미지 관리 모드만 가른다

## 문제 상황

클러스터를 업데이트했다고 보고하면, 8.x 패치와 9.x 메이저 업그레이드, baseline 잔존과 이미지 전환이 한 완료로 섞입니다.

8.0 Release Notes의 Deprecation of vSphere Lifecycle Manager baselines는 legacy vSphere Update Manager 워크플로가 8.0에서 지원되지만 이후 릴리스에서 지원이 떨어진다고 적습니다. baseline 대신 vSphere Lifecycle Manager images를 쓰라고 안내합니다.

8.0 Images 문서는 클러스터 생성 때 이미지를 두거나, 기존 baseline 클러스터를 나중에 이미지로 바꿀 수 있다고 적습니다. If you switch to using images, you cannot revert to using baselines for that cluster. You can only move the hosts to a cluster that uses baselines.

9.1 Baselines and Images 문서는 With vSphere 9.0, upgrading to the latest version of ESX is only possible using vSphere Lifecycle Manager images라고 적습니다. 9.0에서 baseline과 baseline groups로 할 수 있는 일은 8.x 호스트 업데이트와 패치로 한정합니다. KB 379388은 vSphere 9.0에서 VUM 기반 baseline의 주요 기능 제거를 알리고, 8.x는 패치와 Rollup bulletin은 가능하나 ESX Host(s) can't be upgraded to 9.x through ISO라고 적습니다.

## 지금 결정할 것

- 각 클러스터의 Updates 화면이 Image인지 Baselines인지
- 8.x 패치만 남기고 baseline을 유지할지, 9.x 메이저 전에 이미지로 바꿀지
- 이미지 전환을 이번 창에 넣을지, 호스트를 옮길 baseline 클러스터를 남겨 둘지
- ISO로 9.x를 올린다는 계획을 baseline 클러스터에 남겨 두지 않을지
- 전환 후 되돌릴 수 없음을 승인 조건에 남길지

## 의사결정 기준

### 8.x 패치와 9.x 업그레이드를 한 관리 모드로 보지 않습니다

9.1 문서와 KB는 8.x 패치를 baseline으로 남길 수 있다고 적습니다. 최신 ESX로의 업그레이드는 이미지로만 가능합니다. 8.x 패치 성공을 9.x 준비 완료로 보지 않습니다.

### 이미지 전환은 그 클러스터에서 되돌릴 수 없습니다

8.0 Images 문서는 전환 후 baseline으로 되돌릴 수 없고, 호스트를 baseline 클러스터로 옮기는 것만 남는다고 적습니다. 시험 클러스터 없이 운영 클러스터를 이미지로 바꾸지 않습니다.

### ISO 업그레이드를 이미지 전환으로 보지 않습니다

KB는 VUM 경로에서 9.x ISO 업그레이드가 안 된다고 적습니다. 8.0 비교 문서는 이미지 구성에 ISO를 쓸 수 없다고 적습니다. ISO 미디어만 준비했다고 이미지 관리로 바뀌었다고 보지 않습니다.

### 폐기와 제거를 같은 날로 보지 않습니다

8.0 Release Notes는 이후 릴리스에서 지원이 사라진다고 적습니다. 9.1 문서는 8.0에서 폐기, 9.0에서 제거라고 적습니다. 8.0 잔존 클러스터를 이미 제거된 상태로 보고하지 않습니다.

## 실무 체크리스트

1. vSphere Client에서 클러스터별로 Updates 화면이 Image인지 Baselines인지 기록합니다.
2. 8.x 패치만 필요한 클러스터와 9.x 메이저가 필요한 클러스터를 나눕니다.
3. baseline 클러스터에 9.x ISO 업그레이드 계획이 있으면 이미지 전환 전제로 바꿉니다.
4. 이미지로 바꿀 클러스터의 되돌릴 수 없음을 승인자에게 알립니다.
5. 전환 실패 시 호스트를 옮길 baseline 클러스터가 있는지 적습니다.
6. 8.0 predefined baseline이 VMware 콘텐츠만인지 Release Notes 제한을 확인합니다.
7. 전환 후 Updates가 Image로 보이는지, Baselines로 되돌리는 메뉴가 없는지를 확인합니다.
8. 주간 점검: 메이저 업그레이드 대상이 아직 Baselines이면 FAIL로 남깁니다.

## 제외 범위

- vSAN HCI와 vSAN Max 클러스터 유형 글의 재작성
- NVIDIA-Certified Hypervisor 인증 글의 재작성
- 고객 클러스터의 업그레이드 시간, 성능, 무중단 보장
- 하이퍼바이저 제품의 우열, 가격 비교
- 홈페이지·상포코리아 카피 변경
