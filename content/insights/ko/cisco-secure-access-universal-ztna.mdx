## 한눈에 보기

Cisco Secure Access Universal ZTNA는 사용자 신원으로 사설 자원 접근을 허용하고, RA-VPN처럼 네트워크 전체를 여는 방식과 대비됩니다. 정책 평가는 클라우드에 남고 데이터 경로는 FTD에 남을 수 있습니다.

- 결정: 클라우드 강제, 로컬 FTD 강제, TND로 경로를 나눌지, 민감 앱은 항상 로컬로 둘지
- 전제: 기술 문서는 FTD 7.7.10, FMC 7.7.10, Secure Client ZTA 5.1.10. Hybrid ZTNA 기능 플래그는 TAC에 요청할 수 있다
- TND: 신뢰 네트워크로 보이면 클라이언트가 경로를 바꾸고, 정책 평가는 Secure Access 클라우드가 수행
- 범위: Prisma Access 에이전트리스 글이나 FortiSASE 글이 아니라 Cisco 경로 경계

## 문제 상황

ZTNA를 켰다고 보면, 클라우드에서 검사하는 앱과 사내 FTD만 지나는 앱이 한 정책 이름으로 섞입니다.

225858 기술 문서는 2026-05-06 갱신입니다. Universal ZTNA는 사용자 신뢰와 자세를 포함해 내부 자원만 열고, RA-VPN처럼 네트워크 전체에 접근을 주지 않는다고 적습니다. Secure Access가 접근 정책을 평가하고, FMC에서 장비로 내린 접근 제어 정책은 무시된다고 적습니다. 트래픽 프록시와 IPS, 파일, 악성코드 정책 강제는 FTD에서 수행한다고 적습니다.

클라우드 또는 로컬 강제를 고르고 TND 규칙을 FTD에 연결하면, 클라이언트가 네트워크 지문을 평가해 헤더에 실어 보냅니다. 지문이 맞으면 데이터 경로를 FTD로, 아니면 클라우드로 돌린다고 적습니다. 온프레미스 사용자는 인증과 평가는 Secure Access로 가고 데이터 경로만 방화벽으로 갈 수 있다고 적습니다. 민감 애플리케이션은 데이터가 클라우드를 거치지 않고 항상 방화벽을 지나게 구성할 수 있다고 적습니다.

헬프 문서 140154는 확인일 기준 Last updated Aug 27, 2026입니다. Manage Client-Based Zero Trust Access와 Manage Threat Defense Devices for Universal Zero Trust Network Access 항목이 있습니다. 225407은 2026-03-30 갱신이며, TND가 신뢰 네트워크에서 ZTA 스티어링과 강제를 잠시 멈추고, 떠나면 다시 켠다고 적습니다. 사용자 조작은 필요 없습니다. FMC Universal ZTNA 구성 가이드는 민감 앱의 enforcement point를 Local only로 두라고 적습니다.

## 지금 결정할 것

- 앱을 클라우드 강제, 로컬 FTD 강제, TND 기반 동적 경로, 항상 로컬 중 무엇으로 둘지
- Hybrid ZTNA 기능 플래그를 TAC에 요청할지
- TND 프로파일의 DNS, 도메인, 인증서 해시를 어떤 네트워크에 둘지
- RA-VPN 전체 네트워크 접근을 남길 사용자와 ZTNA만 줄 사용자를 나눌지
- FTD 7.7.10과 Secure Client ZTA 5.1.10 전제를 만족할지

## 의사결정 기준

### 정책 평가와 데이터 경로를 한 강제 지점으로 보지 않습니다

기술 문서는 정책 평가가 Secure Access 클라우드에 있고, 데이터 평면 검사와 프록시는 FTD에 있을 수 있다고 적습니다. FMC 접근 제어 정책을 같은 승인으로 읽지 않습니다. 클라우드에 정책이 있다고 해서 모든 앱 데이터가 클라우드를 지난다고 보지 않습니다.

### TND는 경로 결정이지 RA-VPN 대체 선언이 아닙니다

TND는 신뢰 네트워크에서 스티어링을 멈추거나 로컬 강제 경로를 고르는 조건입니다. RA-VPN이 네트워크 전체를 여는 대비로만 적혀 있습니다. TND를 켰다고 해서 원격 접속을 모두 대체했다고 내부 보고하지 않습니다. 신뢰 서버는 ZTA 가로채기에서 빠지며 사설 자원으로도 쓰지 못한다고 225407이 적습니다.

### 민감 앱의 항상 로컬과 동적 경로를 한 프로필로 묶지 않습니다

민감 데이터 앱은 항상 방화벽을 지나게 할 수 있습니다. FMC 가이드는 Local only를 민감 앱에 쓰라고 적습니다. 일반 앱의 Cloud or Local과 같은 변경 요청에 넣지 않습니다.

### 기능 플래그와 소프트웨어 열차를 전제로 적습니다

Hybrid ZTNA 기능 플래그는 테넌트에 켜져 있어야 하며 TAC에 요청한다고 225858이 적습니다. 구성 예시는 FTD 7.7.10과 Secure Client ZTA 5.1.10입니다. 플래그 없이 콘솔 메뉴만 보고 사용 가능으로 보지 않습니다.

## 실무 체크리스트

1. 사설 앱을 클라우드 강제, 로컬 강제, TND 동적, 항상 로컬로 나눕니다.
2. Secure Access 테넌트에 Hybrid ZTNA 플래그가 있는지, TAC 요청이 필요한지 기록합니다.
3. FTD, FMC, Secure Client ZTA 버전을 문서 예시와 대조합니다.
4. TND 프로파일의 DNS, 도메인, 인증서 해시와 제외 서버를 적습니다.
5. RA-VPN을 유지할 사용자와 ZTNA만 줄 사용자를 분리합니다.
6. 정책 평가 담당 클라우드와 데이터 경로 담당 FTD를 앱별로 남깁니다.
7. 민감 앱의 Local only 선택을 일반 앱 동적 경로와 섞지 않습니다.
8. 적용 후 신뢰 네트워크와 비신뢰 네트워크에서 실제 경로를 누가 확인하는지 정합니다.
