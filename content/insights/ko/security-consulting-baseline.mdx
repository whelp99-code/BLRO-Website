보안 컨설팅을 장비 목록이나 정책 문서 목록에서 시작하면, 실제로 누가 무엇에 접근하는지 빠지기 쉽습니다. 먼저 필요한 것은 **사용자·장치·애플리케이션·데이터·지점 사이의 접근 흐름 지도**입니다. 이 지도가 있어야 통제 공백과 운영 책임을 같은 대화에서 다룰 수 있습니다.

## 첫 인터뷰에서 확인할 5개 축

| 축 | 확인 질문 | 남겨야 할 결과 |
| --- | --- | --- |
| 사용자 | 임직원·협력사·관리자는 왜 접근하는가 | 역할별 접근 목적 |
| 장치 | 관리·비관리 장치의 정책은 다른가 | 장치 신뢰 기준 |
| 애플리케이션 | 어디에 있고, 어떤 인증·연동을 쓰는가 | 앱별 접근 경로 |
| 데이터 | 어떤 데이터가 어느 경계로 이동하는가 | 보호 우선순위 |
| 운영 | 권한·예외·사고·복구를 누가 승인하는가 | 책임과 변경 절차 |

## 진단 산출물

1. 현재 접근 흐름과 신뢰 경계 지도
2. 사용자·장치·애플리케이션별 통제 요구사항 표
3. 우선순위·전환 순서·검증 조건이 포함된 개선 로드맵
4. 정책 예외, 권한 회수, 사고 대응과 운영 인수 기준

## 실제 흐름으로 검증하는 방법

설계안은 문서 검토만으로 끝내지 않습니다. 신규 사용자 권한 부여, 협력사 원격접속, 장치 변경, 정책 예외, 인증 장애, 권한 회수 시나리오를 따라가며 통제가 어디에서 작동하고 누가 조치하는지 확인합니다. NIST의 Zero Trust 원칙도 네트워크 위치보다 리소스 보호와 세분화된 인증·인가에 초점을 둡니다. [NIST SP 800-207](https://csrc.nist.gov/pubs/sp/800/207/final)

## 흔한 오류

새 보안 제품을 도입하면 위험이 자동으로 줄어든다고 보거나, 로그 수집을 관제로 간주하는 오류가 있습니다. 통제 범위가 정해져도 예외 승인·권한 회수·장애 대응의 책임자가 없으면 운영 위험은 남습니다. 반대로 모든 흐름을 한 번에 바꾸려 하면 업무 중단 가능성이 커집니다. 우선순위가 높은 흐름부터 검증하고, 나머지는 전환 순서로 관리해야 합니다.

## 다음 행동

접근 흐름 지도를 만들면 원격접속 방식, 네트워크 경계, SASE·SD-WAN 역할, 로그 운영 범위를 각각 비교할 수 있습니다. 네트워크 보안 진단에서는 이 지도를 바탕으로 현재 환경에서 먼저 검증할 사용자군과 애플리케이션을 정리합니다.
