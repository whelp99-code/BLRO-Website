## 한눈에 보기

VDI 또는 클라이언트리스 엔드포인트의 Gateway 프록시를 출발지 IP만으로 둘지, Cloudflare One의 Networks, Resolvers and Proxies, Proxy endpoints에서 Authorization endpoint와 hosted PAC로 바꿀지를 이번 주 결정합니다.

- 결정: 출발지 IP 프록시를 유지할지, Cloudflare Access로 인증하는 Authorization proxy와 hosted PAC로 바꿀지
- 전제: Changelog는 2026-04-29에 두 기능이 모든 플랜 유형에서 generally available이라고 적는다. Source IP proxy endpoints는 Enterprise 플랜만 쓸 수 있다
- 운영: Cloudflare One에서 Networks, Resolvers and Proxies, Proxy endpoints의 엔드포인트 종류와 hosted PAC URL을 읽는다
- 범위: 확인일 기준 404인 policies/gateway/proxy-endpoints 경로는 근거로 쓰지 않는다. 생성 후 타입은 바꿀 수 없다

## 문제 상황

프록시를 켰다고 보고하면, 출발지 IP 허용과 Access 로그인, 브라우저 PAC와 클라이언트 설치가 한 완료로 섞입니다.

Cloudflare Changelog, April 29, 2026는 Gateway Authorization Proxy and hosted PAC files are now generally available for all plan types라고 적습니다. Authorization proxy endpoints add an identity-aware option alongside the existing source IP proxy endpoints, using Cloudflare Access authentication to verify who a user is before applying Gateway filtering, without installing the Cloudflare One Client. Cloudflare-hosted PAC files let you create and distribute PAC files directly from Cloudflare One. These features are ideal for environments where deploying a device client is not an option, such as virtual desktops (VDI) or compliance-restricted endpoints.

Proxy endpoints 문서는 Source IP proxy endpoints are only available on Enterprise plans라고 적습니다. 엔드포인트 종류는 authorization endpoints와 source IP proxy endpoints입니다. Once you create a proxy endpoint, you cannot change its type. Authorization endpoints는 Cloudflare Access로 로그인하고 Access 정책을 통과해야 합니다. Source IP endpoints는 미리 넣은 출발지 IP만 허용합니다. 콘솔 경로는 Cloudflare One에서 Networks, Resolvers and Proxies, 이어서 Proxy endpoints입니다. Authorization은 Add an authorization endpoint, 출발지 IP는 Add a source IP endpoint입니다.

hosted PAC는 Cloudflare One에서 만들어 공개 Worker로 배포합니다. URL 형식은 https://pac.cloudflare-gateway.com/와 account-id, slug입니다. slug는 만든 뒤 바꿀 수 없습니다. Authorization endpoints require TLS inspection on all proxied traffic. account 수준에서 TLS decryption을 꺼도 Authorization 경로 트래픽은 복호화합니다. Safari와 iOS/iPadOS는 HTTPS 프록시 타입을 지원하지 않습니다.

PAC file best practices는 FindProxyForURL에서 HTTPS 지시어를 쓰고 PROXY를 쓰지 말라고 적습니다. Modern browsers do not support HTTPS proxies without PAC files. iOS와 iPadOS는 지원하지 않습니다.

Configure a PAC file on your device는 Chromium 기반 브라우저는 OS 프록시를 쓰고, Firefox는 Settings, Network Settings, Automatic proxy configuration URL을 따로 둔다고 적습니다. Windows GPO는 User Configuration, Preferences, Windows Settings, Registry의 AutoConfigURL입니다.

## 지금 결정할 것

- 대상이 VDI 또는 클라이언트 설치가 금지된 엔드포인트인지
- 출발지 IP가 고정인지, 사용자 단위 식별이 필요한지
- Authorization endpoint를 새로 만들지, 기존 source IP endpoint를 유지할지
- hosted PAC를 Cloudflare One에서 만들지
- TLS inspection 상시와 Safari·iOS 제외를 전제로 둘지

## 의사결정 기준

### 출발지 IP와 Access 인증을 한 엔드포인트로 보지 않습니다

종류는 만든 뒤 바꿀 수 없습니다. source IP만 있는 엔드포인트에 사용자가 로그인했다고 식별이 생겼다고 보지 않습니다. 다른 인증이 필요하면 새 엔드포인트를 만듭니다.

### Enterprise 출발지 IP를 모든 플랜 GA로 적지 않습니다

Changelog의 GA는 Authorization Proxy와 hosted PAC입니다. Source IP proxy endpoints는 Enterprise만 쓸 수 있다고 같은 문서 집합이 적습니다. 비-Enterprise에서 출발지 IP를 골랐다고 GA를 쓴 것으로 보지 않습니다.

### PAC 없이 브라우저 프록시 칸만 채우지 않습니다

best practices는 HTTPS 프록시를 PAC 없이 브라우저에 직접 넣지 말라고 적습니다. PROXY 지시어를 쓴 PAC를 HTTPS 엔드포인트에 쓰지 않습니다.

### Safari·iOS를 같은 PAC 범위에 넣지 않습니다

Safari와 iOS/iPadOS는 HTTPS 프록시 타입을 지원하지 않습니다. Chromium 또는 Firefox, 그리고 가능한 곳의 Cloudflare One Client를 대안으로 적습니다.

## 실무 체크리스트

1. 대상을 VDI·클라이언트리스와 Cloudflare One Client 설치 가능 단말로 나눕니다.
2. Cloudflare One에서 Networks, Resolvers and Proxies, Proxy endpoints를 엽니다.
3. 기존 엔드포인트가 Add a source IP endpoint인지 Add an authorization endpoint인지 기록합니다.
4. 사용자 단위 식별이 필요하면 Authorization endpoint를 새로 만들고 Access 정책을 붙입니다.
5. 같은 화면에서 Add PAC files로 hosted PAC를 만들고 slug를 확정합니다.
6. PAC URL이 pac.cloudflare-gateway.com 형식인지 확인합니다.
7. Authorization을 쓰면 TLS inspection이 꺼지지 않음을 변경 기록에 남깁니다.
8. Windows는 AutoConfigURL, Firefox는 Automatic proxy configuration URL, Safari·iOS는 제외로 적습니다.
