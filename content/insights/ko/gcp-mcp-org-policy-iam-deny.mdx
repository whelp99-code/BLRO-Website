## 한눈에 보기

Google Cloud MCP 폐기 문서는 gcp.managed.allowedMCPServices와 조직 정책 통제가 2026-02-17에 폐기되고 2026-03-17에 종료된다고 적습니다. 같은 날 릴리스 노트는 지원 제품을 켜면 원격 MCP 엔드포인트가 기본으로 열린다고 적습니다.

- 결정: 예전 조직 정책 허용 목록을 IAM 거부와 허용으로 다시 쓸지, 읽기 전용만 남길지
- 전제: 도구 호출에는 mcp.tools.call과 대상 리소스 권한이 둘 다 필요하다고 IAM 문서가 적는다
- 불일치: 조직 정책 릴리스 노트는 2026-02-15에 같은 종료를 알리고, MCP 폐기 페이지는 폐기일을 2026-02-17로 적는다
- 범위: 에이전트 설계가 아니라 프로젝트·폴더·조직의 MCP 호출 통제 경계

## 문제 상황

조직 정책으로 MCP 서비스를 허용 목록에 두던 통제는 2026년 3월 17일 이후 동작하지 않습니다. 같은 날부터는 지원 제품을 켜면 원격 MCP가 기본으로 열립니다.

폐기 페이지는 종료 후 IAM 거부로 누가 Google과 Google Cloud MCP 서버를 쓰는지 관리하라고 적습니다. 사용자는 mcp.tools.call이 있어야 프로젝트에서 도구를 호출합니다. IAM 문서는 이 권한과 대상 리소스 권한이 모두 있어야 하고, 하나만 있으면 실패한다고 적습니다.

2월 17일 릴리스 노트는 그 전에 만든 조직 정책은 3월 17일 이후 동작하지 않고, 제약 조건을 쓰지 않던 조직은 2월 17일부터 쓸 수 없다고 적습니다. 3월 17일 노트는 제약이 더 이상 동작하지 않으며, 원격 MCP를 따로 켤 필요가 없다고 적습니다. 조직 정책 서비스 릴리스 노트는 2월 15일 항목에서 3월 17일 이후 같은 제약이 동작하지 않는다고만 적습니다.

거부 정책은 주체, 읽기 전용 여부, 서비스 이름, 도구 이름, OAuth 클라이언트 ID로 나눌 수 있습니다. 콘솔에서는 resource.service와 tool.name을 쓸 수 없고 gcloud로 관리한다고 적습니다. Resource Manager MCP는 이 속성으로 통제할 수 없습니다.

## 지금 결정할 것

- 3월 17일 이후에도 남아 있는 조직 정책 제약을 유효한 통제로 보지 않고 IAM으로 옮길지
- 프로젝트 기본 개방을 조직·폴더 거부로 덮을지
- 읽기 전용만 허용할지, 특정 서비스나 도구만 허용할지
- mcp.tools.call과 리소스 권한을 같은 역할에 묶지 않을지
- Resource Manager MCP를 별도 통제로 둘지

## 의사결정 기준

### 조직 정책 허용 목록과 IAM 거부를 같은 스위치로 보지 않습니다

폐기된 제약은 서비스 허용 목록이었습니다. IAM 문서는 거부 정책으로 전체 차단, 읽기 쓰기 차단, 서비스 예외, 클라이언트 ID 예외를 나눕니다. 예전 목록을 한 줄로 옮기지 말고, 누가 어떤 서비스의 어떤 도구를 호출하는지 다시 적습니다.

### 제품 활성화와 MCP 호출 권한을 한 승인으로 두지 않습니다

3월 17일 노트는 지원 제품을 켜면 원격 MCP가 기본으로 열린다고 적습니다. 호출에는 여전히 mcp.tools.call이 필요합니다. 제품을 켰다고 에이전트나 사용자에게 도구 호출을 준 것은 아닙니다. 기본 개방과 호출 권한을 같은 변경 요청서에 나눕니다.

### 폐기일 기록은 MCP 폐기 페이지를 운영 기준으로 둡니다

조직 정책 릴리스 노트는 2월 15일, MCP 폐기 페이지와 폐기 표는 2월 17일 폐기·3월 17일 종료입니다. 운영 기록에는 두 날짜를 남기고, 종료 사실과 대체 통제는 MCP 폐기 페이지와 IAM 문서를 엽니다.

### 콘솔로 못 쓰는 속성과 Resource Manager 예외를 빠뜨리지 않습니다

서비스 이름과 도구 이름은 콘솔에 없고 gcloud로만 붙입니다. 클라이언트 ID는 거부 정책에만 있습니다. Resource Manager MCP는 이 속성으로 막을 수 없다고 적습니다. 태그 조건과 MCP 속성을 섞을 수 없습니다.

## 실무 체크리스트

1. 조직에 gcp.managed.allowedMCPServices 할당이 남아 있는지 확인합니다.
2. 지원 제품이 켜진 프로젝트에서 원격 MCP가 기본 열려 있는지 적습니다.
3. 호출 주체에게 mcp.tools.call과 대상 리소스 권한이 있는지를 나눕니다.
4. 전체 차단, 읽기 전용, 서비스 예외, 도구 예외 중 무엇을 쓸지 고릅니다.
5. 조직·폴더·프로젝트 중 거부 정책 부착 지점을 정합니다.
6. resource.service와 tool.name은 gcloud로 관리한다고 운영 절차에 적습니다.
7. Resource Manager MCP를 이 속성 밖으로 두고 별도 검토합니다.
8. 태그 조건과 MCP 속성을 한 정책에 섞지 않습니다.
