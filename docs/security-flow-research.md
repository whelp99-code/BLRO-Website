# 방화벽·IDS·IPS 설명 장면 리서치 (2026-10-22)

홈 보안 섹션에 방화벽, IDS, IPS의 차이를 보여 주는 장면을 넣기 전에 조사한 내용입니다. 확인한 사실과 채택·기각 결정을 구분해 적습니다.

## 1. 풀려는 문제

- 고객이 보안 상담에서 가장 자주 섞어 쓰는 세 용어를 한 화면에서 구분하지 못하면, 상담이 용어 설명에서 시작합니다. 홈의 기존 보안 섹션은 접근·탐지·대응·검증 4개 층만 보여 주고 장치별 차이는 문장으로만 있습니다.
- 숫자로 증명되지 않은 부분: 이 문제가 방문자 이탈이나 상담 전환에 얼마나 영향을 주는지는 측정 자료가 없습니다. 그래서 효과 주장 없이 측정 지표를 먼저 정합니다(아래 7절).

## 3. 기각한 자료와 이유

- SOC 경보 오탐 비율(50~80% 등)을 다룬 벤더 블로그 글: 출처마다 수치가 달라 일반 사실로 쓸 수 없고, 성능 약속과 같은 오해를 줄 수 있어 사이트에 쓰지 않습니다.
- Sangfor 공식 사이트: Cloudflare 403으로 열리지 않아 조사 대상에서 제외했습니다. 제조사 고유 기능 설명은 이 장면에 넣지 않으므로 영향이 없습니다.

## 4. 문제 분해

| 구분 | 내용 | 처리 방식 |
|---|---|---|
| 결정론적 | 패킷 속성(허용 포트 여부, 탐지 패턴)과 장치 구성이 주어지면 허용/차단/경보와 서버 도착 여부는 하나로 정해진다. | 순수 TS 함수 `simulate` (`lib/security-flow.ts`). 모델이나 화면이 판정하지 않는다. |
| 결정론적 | 타임라인(프레임), 가로 위치, 결과 문장 | 같은 파일의 `timeline`, `slotPosition`, `describe` |

| 판단이 필요한 부분 | 문구의 정확성, 톤, 화면 배치 | 출처 대조(위 표), 스크린샷 비교, 사람 검토 |

## 5. 설계 결정

- 잘못된 조합(IDS가 경로 중간에서 차단)은 타입으로 만들 수 없게 했습니다(`ChainElement`).
- 4개 시나리오(방화벽, IDS, IPS, 함께 구성) x 4개 통신으로 16개 판정을 모두 결과 표에 글로 보여 줍니다. 애니메이션은 보조이고, 정보는 글에도 있습니다.
- 3D는 데스크톱 폭에서 화면 근처에 왔을 때만 `three`를 동적 import합니다. 모바일과 모션 감소 설정에서는 2D 그림이 같은 상태를 보여 줍니다.

## 6. 평가 기준 (`scripts/eval-security-flow.mjs`)

같은 소스에서는 항상 같은 점수가 나옵니다. 판정·불변식·결정성·문구는 한 건이라도 어긋나면 점수와 무관하게 실패합니다.

| 항목 | 배점 | 방식 |
|---|---|---|
| 기대표 일치 | 30 | 구현과 따로 규칙 문장에서 도출한 12칸 표와 비교 |
| 불변식 | 20 | 장치 0~3개의 모든 순열 x 4통신 64조합: 도착=경로 중간 차단 없음, IDS는 도착을 바꾸지 않음, 차단 뒤 장치는 보지 못함, 타임라인 단조 증가 |
| 결정성 | 10 | 같은 입력 두 번 실행 결과 비교 |
| 문구 점검 | 15 | 퍼센트·성능 약속·작성 지침식 표현·제조사명 금지 |
| 접근성·모션 | 15 | aria-pressed, aria-live, 도식 대체 텍스트, 모션 감소, 44px 터치 크기, 전체 판정 텍스트 |
| 번들 가드 | 10 | `three` 정적 import 금지, 데스크톱 한정, 화면 근처에서만 로드 |

변이 점검: IPS 판정을 일부러 틀리게 바꾸면 "기대표 일치" 실패로 종료 코드 1, 문구에 성능 수치를 넣으면 "문구 점검" 실패로 종료 코드 1이 나옵니다.

## 7. 효과 측정 계획

- 성능 가드: 홈 Lighthouse 모바일 성능을 추가 전후 같은 조건으로 비교하고 5점 이상 하락하면 3D를 끕니다.
- 사용 지표: 장면 아래 "네트워크와 보안 상세"와 상담 CTA 클릭률을 기존 분석 이벤트 기준으로 추가 전후 비교합니다. 표본이 충분하지 않으면 효과가 있다고 말하지 않습니다.
