BLRO에 쓸 일곱 가지

구현 기본은 CSS scroll-driven과 작은 JS다. GSAP, Lottie, Rive, WebGL은 기본 스택에 넣지 않는다. 경로 모핑이 CSS로 안 되는 섹션이 생기면 그때 한곳만 GSAP를 검토한다. 지금은 그 필요가 없다.

01

스크롤에 묶인 업무 경로

참고: Cloudflare의 한 그림 한 문장. 지구를 베끼지 말고 도입 → 전환 → 구축 → 운영 → 기술지원 노드를 그린다. 고객은 순서, 파트너는 자기 구간, 엔지니어는 산출물 이름을 본다. view()와 stroke/opacity만. reduced motion이면 완성 경로.

02

스티키 한 장면

참고: Linear가 화면을 갈아 끼우는 방식. BLRO는 앱 위조가 아니라 R&R, 역할 맵, 체크리스트를 둔다. 스크롤 소유자는 문서. 섹션당 스테이지 하나. 스크롤을 멈추면 장면도 멈춘다.

03

설명하는 계기판

참고: Stripe 목업, Vercel 채팅, Supabase의 작은 그림. Datadog식 가짜 차트는 피한다. SVG 노드 하나만 신호색으로. 영상 없음.

짧은 등장 — 현행 규칙 유지

세로 12px, 가로 16px, 420–500ms, 스태거 70ms. Raycast·Framer의 상시 배경은 반례. IntersectionObserver가 실패하면 최종 상태가 보인다.

View Transitions. 고객·파트너·엔지니어 전환이 다른 사이트가 아니라 같은 책의 다른 장임을 보여 준다. 300ms 이내. 미지원과 reduced motion은 즉시 전환. 현행 규칙에 없는 항목이라 승인 문장에 적는다.

Stripe GDP 카운터는 그들 숫자다. BLRO는 고객 수, 절감률, SLA를 만들지 않는다. 승인된 사실도 기본은 정적 표기.

로고는 멈추게

Cloudflare 마키는 일시정지가 있어도 무한 모션이다. 승인된 제조사 워드마크만 정지 그리드. 고객 로고는 발명하지 않는다.

승인용 모션 규칙

현행 AGENTS.md 문장을 아래 문장으로 바꾸는 제안이다. 승인 전에는 정본을 고치지 않는다.

모션은 실제 업무의 한 단계를 보여 줄 때만 쓴다. 시간 기반 등장은 세로 12px·가로 16px 이내, 420–500ms, 스태거 70ms, 바운스 없음. 스크롤 연동은 CSS animation-timeline: view() 또는 scroll()로, transform·opacity·stroke만, 문서 스크롤을 빼앗지 않는다. 이야기 섹션당 스티키 스테이지는 하나. 호버는 링크·버튼·다이어그램 노드에만 opacity 또는 1px 이동. 페이지 전환은 역할 홈 사이 300ms 이내 크로스페이드만 허용하고, 미지원·reduced motion에서는 즉시 전환한다. 무한 반복, 커서 추종, 스크롤 하이재킹, WebGL, 자동재생 영상, 카운트업, 모션만으로 전달되는 의미는 금지한다. JavaScript 실패, IntersectionObserver 실패, prefers-reduced-motion: reduce에서는 완성된 내용이 즉시 보인다. 숫자는 승인된 사실만 정적 표기한다.
