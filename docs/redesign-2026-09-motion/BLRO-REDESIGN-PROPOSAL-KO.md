# BLRO 사이트 개편안 — 모션 기반

작성: 2026-09-30. 범위: 제안과 정적 시안. 배포, DNS, TLS, `blro.co.kr`, 미리보기 서비스, 커밋은 하지 않았다. `publishingEnabled`는 건드리지 않았다.

가정: 소유자가 말한 클라우드플레어 참고는 이 서버에 없는 이름의 프로젝트가 아니라 **cloudflare.com 마케팅 사이트의 모션**이다. BLRO 참고는 워크스페이스 2.1.0, `/home/jm/orca/projects/blro-website`, 그리고 공개 사이트 https://blro.co.kr 이다.

## 1. 감사

두 사이트는 같은 회사가 아니다에 가깝다.

| | 공개 https://blro.co.kr | 로컬 2.1.0 `:8771` |
|---|---|---|
| 스택 | Next.js, Cloudflare 앞단 (`cf-ray`) | 자체 Node 정적 빌드, `publishingEnabled` 비공개 |
| 한 줄 | 전환을 운영 판단으로 | 제품 공급·구축 |
| 히어로 | 좌측 대형 한글, 우측 진단 결과물 카드 | 좌측 문장, 우측 단말-보안-VDI-HCI 선도 |
| 모션 | `getAnimations()` 0. 정적인 편집 레이아웃 | 홈에 애니메이션 4. 장식에 가깝고 스크롤 스토리는 없음 |
| IA | Solutions, AI, Projects, Insights, Partner, 진단 CTA | 고객 / 파트너 / 엔지니어 + 솔루션 21 |

캡처: `captures/live/`, `captures/local/`. 뷰포트 1440×900, 390×844. 첫 화면만. 공개 홈 스크롤 높이는 약 10449px, 로컬 홈은 약 5367px.

잘 되는 것

- 공개 홈은 문장이 분명하다. "무엇을 파는지"보다 "무엇을 먼저 검증하는지"가 제목이다.
- CTA가 하나다. 전환 진단.
- 고객명을 꾸미지 않는다. Projects가 판단 과정을 보여 준다.
- 로컬 2.1.0은 제품 경로(단말 → 보안 → VDI/HCI)가 있다. 공개 사이트에 없는 그림이다.
- 로컬은 역할(고객/파트너/엔지니어)이 계약으로 잠겨 있다. 개편이 이 셋을 지우면 안 된다.

약한 것

- 메시지 충돌. 공개 사이트는 컨설팅, 로컬은 공급·구축. 방문자는 어느 쪽이 정본인지 모른다.
- 계층. 공개 홈은 길고, 네 가지 능력이 같은 무게다. 스크롤이 설명을 반복한다.
- 신뢰. 로고·수치를 숨긴 판단은 정직하지만, 대체 증거가 카드 목록에 머문다. 숫자 카운트만 붙이면 더 얕아진다.
- 전환. 진단 CTA는 있으나, 솔루션 페이지에서 "이 페이지를 읽고 무엇을 보내야 하는지"가 약하다.
- 성능·모션. 공개 홈은 모션이 없다. 로컬 다이어그램은 정지 화면이다. Cloudflare식 스크롤 설명에 쓸 재료가 이미 있는데 쓰이지 않는다.
- 모바일. 공개 홈 제목이 화면을 채우고 진단 카드는 접힌다. 로컬은 경로 그림이 제목 아래로 밀린다.

## 2. Cloudflare 모션 참고

본 것: https://www.cloudflare.com/ (2026-09-30, "Build for the agent era"), https://www.cloudflare.com/zero-trust/ (Cloudflare One). 캡처 `captures/cloudflare/`. 자산과 코드는 복사하지 않았다.

관찰한 패턴

- 히어로는 큰 색면과 한 문장. 모션의 주인공은 히어로가 아니라 그 아래 대비 패널이다. 홈에서 `getAnimations()` 약 230. 이름: `canvas-fade-in` 1000ms, `waveform-scroll` 20s linear, `marquee` 8s, `infinite-scroll` 40–80s, `background-pulse` 2s, `float` 5s alternate translateY 0/−8px.
- 스크롤은 설명을 단계로 자른다. Zero Trust는 문제(흰 면)와 해답(주황 면)을 나란히 두고, 수치는 `~3 months`, `~50%`처럼 사례에 붙인다. 숫자만 세지 않는다.
- 스티키 내비게이션은 스크롤 후 작은 "Start building"으로 줄어든다. 본문은 카드 그리드보다 문장 대비가 우선이다.
- 호버는 버튼과 링크에만. 키프레임은 `transform`과 `opacity`. `prefers-reduced-motion`에서 shimmer 등을 끈다.
- 이지잉은 루프에 linear, 진입에 ease-out, 토스트에 `cubic-bezier(0.34, 1.56, 0.64, 1)`.

가져올 것: 한 장면 = 한 주장, 스크롤이 경로를 진행, 대비 패널, 감소 모션. 가져오지 말 것: 주황, 지구본, 마키, 80초 무한 스크롤, 에이전트 카피.

## 3. 제안

### 목표와 독자

목표: 첫 화면에서 "공급사인가, 진단 파트너인가"를 한 문장으로 고정하고, 스크롤이 HCI/VDI/보안이 한 경로임을 보여 준 뒤, 역할별 문의로 보낸다.

독자: 기업 IT 담당(도입·전환), 국내 파트너(공동 수행), 기술 엔지니어(자료). 글로벌 벤더 한국 진출은 공개 사이트에만 있다. 유지 여부는 오너 결정.

### IA

```
/                 경로 히어로 + 4단계 스크롤 + 역할 3
/solutions        HCI, VDI, 네트워크·보안, 백업·DR, SASE
/solutions/hci
/solutions/vdi
/solutions/security
/projects         판단 과정. 고객명 없음
/blro             역할과 하지 않는 일
/contact          역할별 폼
/customer /partner /engineer   2.1.0 계약 유지
```

공개 사이트의 Insights는 유지하되 홈 1차 내비에서는 뺀다. AI & Automation은 솔루션의 한 항목으로 내린다. 둘을 홈 상단에 두면 인프라 경로가 흐려진다.

### 페이지

홈: 키커, 한 문장, 진단 CTA, 우측 경로 계기. 스크롤 4단(범위, 경로, 검증, 인수). 그 다음 역할 3. 그 다음 솔루션 3장. 푸터.

솔루션: 각 페이지 상단은 같은 경로 그림에서 해당 노드만 점등. 본문은 검토 질문 5개, 통과 기준, 하지 않는 약속, 문의에 보낼 정보. 제조사 로고 월은 넣지 않는다.

Projects: 지금 문장 구조를 유지. 모션은 단계 번호가 뷰에 들어올 때만.

회사: 하는 일 / 하지 않는 일. 인증·고객사는 허락 받기 전에는 빈 칸으로 두지 말고 아예 섹션을 뺀다.

문의: 역할 선택 → 그 역할이 준비할 목록이 스크롤 없이 교체. 레이아웃 속성 애니메이션 금지.

### 모션 시스템

원칙: 모션은 경로의 진행만 말한다. 장식 루프 금지.

| 토큰 | 값 |
|---|---|
| 진입 | 420ms, `cubic-bezier(0.22, 1, 0.36, 1)`, opacity + translateY 12px |
| 호버 | 180ms, translateY -1px. 링크와 버튼만 |
| 경로 | `animation-timeline: view()`, stroke-dashoffset. 시간 애니 아님 |
| 스태거 | 70ms, 최대 4개 |
| 카운터 | 쓰지 않음. 사례 숫자가 생기면 한 번만, reduced-motion이면 최종값 |
| 예산 | 홈 JS 모션 0에 가깝게. 폴백만 IntersectionObserver. 동시 무한 애니 0 |
| 감소 모션 | 경로 완성 상태, 펄스 없음 |
| 모바일 | 스티키 다이어그램 해제. 경로는 히어로 아래 한 장. 핀 섹션 금지 |

구현: CSS scroll-driven이 1순위. 워크스페이스에 GSAP이 없고, 상업 라이선스와 번들을 피할 수 있다. Motion One은 문의 폼 역할 전환처럼 CSS로 부족한 상태 전환에만 2단계. GSAP ScrollTrigger는 핀 스토리가 실제로 필요할 때. 지금은 핀 없이 sticky로 충분하다.

### 시각

공개 사이트의 종이·네이비 문장과 로컬의 그린 신호를 합친다. 토큰은 `DESIGN.md`. 액션은 공개 사이트의 파랑 하나. 그린은 검증된 노드만. 파트너 구리는 글자에만. 사이드 컬러 보더 없음.

타입: Pretendard. 디스플레이는 좌측, 데스크톱 68px 상한(기존 65px 가이드와 맞춤). 그리드: 1120, 본문 38–42자.

### 콘텐츠

- 정본 문장 하나를 고른다. 권고: "제품 공급과 전환 검증을 한 경로로 맡깁니다." 공개 사이트의 진단과 로컬의 공급을 둘 다 지우지 않는다.
- Sangfor 등 제조사명은 솔루션 본문에만. 히어로 키워드 나열 금지.
- 승인되지 않은 고객명·수치 금지. 지금 공개 사이트의 그 원칙을 유지한다.

### 기술

공개 사이트는 Next + Cloudflare. 로컬 2.1.0은 자체 서버이며 `functions/`가 있어도 공개 배포 정본으로 확인되지 않았다. 모션은 정본으로 고른 쪽에만 넣는다. 권고는 공개 Next를 정본으로 두고, 2.1.0의 경로 그림과 역할 계약을 내용으로 가져오는 것이다. Cloudflare Pages로 2.1.0을 다시 배포하는 작업은 이 제안의 범위가 아니다.

### 단계와 공수

| 단계 | 내용 | 공수 |
|---|---|---|
| 0 | 오너가 정본 문장과 IA에서 Insights/벤더 유지 여부 결정 | 0.5일 |
| 1 | 홈 + 모션 시스템. 기존 페이지 유지 | 4–6일 |
| 2 | HCI/VDI/보안 세 페이지에 경로 점등 | 4일 |
| 3 | Projects, 회사, 문의 역할 전환 | 3일 |
| 4 | 고객/파트너/엔지니어를 공개 IA에 연결. 계약 테스트 유지 | 5–8일 |
| 5 | 감소 모션, 키보드, 모바일 실기기 | 2일 |

위험: 두 코드베이스를 동시에 고치면 정본이 다시 갈라진다. 고객 로고를 모션으로 대체하려는 유혹. 핀 섹션은 모바일에서 스크롤을 가둔다. 공개 측정 배너는 유지하되 히어로 모션과 겹치지 않게 한다.

## 4. 시안

`prototype/index.html`. 히어로 + 스크롤 스토리. CSS `view()` 타임라인, 미지원 브라우저는 IntersectionObserver. `prefers-reduced-motion`이면 경로가 완성 상태다.

캡처: `captures/proto/desk-s0.png`, `desk-s18.png`, `desk-s38.png`, `desk-s62.png`, `m0.png`, `m40.png`, `m80.png`.

## 5. 오너에게 물을 것

1. 정본은 공개 사이트의 진단 문장인가, 2.1.0의 공급·구축 문장인가, 둘을 한 문장으로 합칠 것인가.
2. 글로벌 벤더 한국 진출과 Insights를 1차 내비에 남길 것인가.
3. 고객명·수치가 아직 비공개인데, Projects를 더 늘릴 자료가 있는가.
4. 구현은 공개 Next에 할 것인가, 2.1.0에 할 것인가. 이 문서는 구현하지 않았다.
