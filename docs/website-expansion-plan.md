# BLRO 공개 웹사이트 확장 계획

## 목표

홈페이지가 약속한 내용을 상세 페이지가 증명하도록 하고, 기업 고객·국내 파트너·글로벌 벤더가 자신의 시작점을 빠르게 찾게 한다. 고객명, 도입 수치, 계약 조건처럼 공개 근거가 없는 정보는 사용하지 않는다.

## 공개 정보 구조

| 경로 | 방문자 질문 | 공개할 내용 | 전환 |
| --- | --- | --- | --- |
| `/blro` | BLRO는 어떤 역할을 하는가 | 진단·검증·전환·안정화 방식과 수행 원칙 | 기술 프로젝트 상담 |
| `/partner-business` | 함께 사업할 수 있는가 | 공동 제안, 기술 검증, 수행 인수의 역할 구분 | 파트너 협업 문의 |
| `/ai-automation` | AI를 어디에, 어떻게 적용하는가 | 운영 자동화 후보, 사람 승인, 보안·감사 기준 | 자동화 검토 상담 |
| `/projects` | 실제로 어떤 문제를 다루는가 | 고객 식별 정보 없는 상황 중심 수행 시나리오 | 현재 과제 상담 |

## 콘텐츠 원칙

1. 제품 우열이나 성능·비용·고객 성과를 검증 없이 단정하지 않는다.
2. Projects는 레퍼런스가 아니라 `상황 → 판단 기준 → 검증·산출물` 형식의 익명 수행 시나리오로만 공개한다.
3. 모든 페이지는 대상별 상담 유형으로 연결하고, 개인정보 처리 안내와 같은 동의 흐름을 유지한다.
4. 고객명, 업종, 회신 SLA, 공식 파트너 자격, 실제 수행 결과는 확인받기 전까지 넣지 않는다.

## 구현 순서

1. 공통 전략 페이지 레이아웃과 반응형·접근성 스타일을 만든다.
2. BLRO 소개, Partner Business, AI & Automation, Projects 페이지를 완성한다.
3. 준비된 페이지를 상단·하단 내비게이션, 사이트맵, 메타데이터에 연결한다.
4. 라우트·링크·SEO 테스트, 정적 빌드, 미리보기 배포로 검증한다.

## 완료 기준

- 모든 공개 메뉴와 CTA가 실제 200 응답 페이지 또는 상담 유형으로 이어진다.
- 각 페이지는 역할, 판단 기준, 산출물 또는 검증 흐름, 다음 행동을 포함한다.
- Projects에 고객 식별 정보, 성과 수치, 미승인 벤더 비교가 없다.
- 미리보기는 검색 노출을 막고, 운영 도메인 연결 뒤에만 인덱싱을 전환한다.

## 내일 확인할 정보

- 실제 회신 가능 시간과 상담 담당 연락 기준
- 공개 가능한 익명 사례의 산업·범위·검증 결과
- 공식 파트너 자격 또는 공개 가능한 벤더 관계
- `blro.co.kr` DNS 이전과 Microsoft 365 레코드 이관 승인
