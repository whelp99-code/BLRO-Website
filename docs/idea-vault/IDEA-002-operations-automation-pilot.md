# IDEA-002 — 6주 운영업무 자동화 파일럿

- 상태: 검증 예정
- 우선순위: P1
- 최초 기록일: 2026-07-15
- 마지막 검토일: 2026-07-15

## 한 문장 제안

반복입력·누락·승인지연이 발생하는 업무 하나를 6주 안에 접수, 승인, 기록, 후속처리가 연결된 실제 운영 흐름으로 바꾼다.

## 고객

- 구매 결정자: COO, 운영 책임자, 영업 책임자, IT·디지털전환 책임자
- 실제 사용자: 영업·프로젝트·재무·고객지원 실무자
- 영향을 받는 사람: 관리자, 내부통제·감사 담당자, 고객

## 고객의 현재 문제

- 이메일, 메신저, CRM, 엑셀 사이에서 같은 정보를 반복 입력한다.
- 문의·승인·후속조치가 특정 담당자의 기억과 메일함에 의존한다.
- 영업에서 프로젝트와 재무로 넘어갈 때 정보가 빠지거나 다시 작성된다.
- 진행상태와 책임자를 한눈에 확인하기 어렵다.
- 시스템 전체 교체는 비용과 변화 부담이 커 시작하지 못한다.

## 고객이 얻는 혜택

- 반복입력과 담당자 의존을 줄인다.
- 누락된 문의와 승인 대기 업무를 확인할 수 있다.
- 업무별 상태, 담당자, 처리이력이 남는다.
- 기존 도구를 유지하면서 문제 구간부터 개선할 수 있다.
- 확대 투자 전에 실제 효과와 운영 위험을 확인할 수 있다.

## 고객이 받는 결과

- 현재 업무 흐름과 병목 분석
- 자동화 단계와 사람의 승인 단계 구분
- 기존 이메일·CRM·업무도구를 연결한 업무 파일럿
- 예외처리와 복구 절차
- 상태·처리이력 확인 화면 또는 기록
- 실무자 운영 매뉴얼
- 확대·수정·중단을 판단하는 효과보고서

## 효과 측정

- 업무 1건의 평균 처리시간
- 수작업 재입력 횟수
- 누락·재작업·반려 건수
- 승인 대기시간
- 상태 확인을 위한 별도 문의 횟수

## 검증할 가설

- 고객은 범용 AI 소개보다 구체적인 업무 하나의 운영 개선에 비용을 지불한다.
- 기존 시스템을 교체하지 않는 접근이 도입 장벽을 낮춘다.
- 의사결정자에게는 자동화율보다 누락, 책임, 처리시간 개선이 더 중요하다.

## 다음 검증 행동

1. 후보 고객의 반복업무를 인터뷰하고 시작 전 기준선을 측정한다.
2. 접점과 예외가 제한된 업무 한 개를 파일럿 후보로 선택한다.
3. 6주 안에 검증 가능한 완료조건과 사람의 승인 지점을 확정한다.

## 하지 않는 것

- 회사 전체 업무를 한 번에 자동화하지 않는다.
- 사람의 승인 없이 중요한 외부 메시지나 금전 업무를 실행하지 않는다.
- 기준선 없이 생산성 향상률을 약속하지 않는다.
